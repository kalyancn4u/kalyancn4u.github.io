Quick Reference · deep learning in Python · Keras 3.15 (Jun 2026)

keras + keras_preprocessing · tensorflow · torch

Keras is an API, not a runtime. You describe layers and models; a backend — JAX, TensorFlow, PyTorch, or OpenVINO for inference — actually executes them. You choose it with one environment variable before the import, and a model built only from built-in layers runs unchanged on any of them. Everything below follows from that one separation.

One API, four runtimes
import os
os.environ["KERAS_BACKEND"] = "jax"   # or "tensorflow" | "torch" — BEFORE the import
import keras

model = keras.Sequential([
    keras.layers.Rescaling(1./255),        # preprocessing IS a layer now
    keras.layers.Dense(128, activation="relu"),
    keras.layers.Dense(10),                  # logits, no softmax
])
model.compile(optimizer="adam",
              loss=keras.losses.SparseCategoricalCrossentropy(from_logits=True),
              metrics=["accuracy"])
model.fit(train_data, epochs=5, validation_data=val_data)
model.save("m.keras")                       # extension is mandatory

# train_data may be NumPy, a tf.data.Dataset, a torch DataLoader,
# or a keras.utils.PyDataset — on ANY backend.
Change one string on line 2 and the same model trains on a different framework.
PART I

keras  ·  the core

Keras 3 is a full rewrite: the same API you know, reimplemented over four backends. Anything built only from built-in layers is portable today — existing tf.keras models included. Custom code is portable only if you write it with keras.ops instead of tf.* or torch.*.
01Install & the backend switchthe first decision
  • pip install keras★
    Keras 3.15 (Jun 2026). Python 3.11+ since 3.13.
  • pip install jax | tensorflow | torch★
    Keras installs no backend for you — pick at least one.
  • os.environ["KERAS_BACKEND"] = "torch"order
    Before import keras. It cannot be changed once imported.
  • ~/.keras/keras.json
    The persistent alternative: {"backend": "jax", "floatx": "float32"}.
  • keras.config.backend()
    Confirm which one is live.
  • keras.config.set_floatx("float16") · set_epsilon
    Global numeric defaults.
  • which backend?
    JAX for speed and TPU, TensorFlow for tf.data and serving, PyTorch to fit an existing codebase, OpenVINO for CPU inference.
  • import tensorflow as tf, then set the variable★
    Too late — importing TF imports Keras. Set the environment variable at the very top of the file.
  • pip install keras --upgrade
    Keras releases far more often than the backends do; upgrading it alone is usually safe.
  • pip install tensorflowsubtle
    Still worth installing even on JAX or torch — some preprocessing layers and every tf.data pipeline need it.

03keras.opswrite once, run anywhere
  • keras.ops.matmul · sum · reshape · stack★
    The NumPy API, reimplemented over every backend.
  • keras.ops.softmax · conv · relu · one_hot
    The neural-network ops NumPy never had.
  • replace tf.* or torch.* with keras.ops.*★
    The portability rule, in one line. Do it in custom layers, losses and metrics.
  • keras.ops.image · linalg · fft · einops · nn
    The sub-namespaces.
  • keras.ops.convert_to_tensor(x) · convert_to_numpy(x)
    Backend-neutral in and out.
  • keras.ops.shape(x) · x.shape
    ops.shape works symbolically too, which x.shape may not.
  • ops on a symbolic KerasTensor compute nothing★
    While building a Functional model they infer the output spec only. That is by design.
  • keras.ops.cast(x, "float32") · cond · while_loop · scan
    Dtype and control flow, portably. A Python if on a tensor breaks under JAX tracing.
  • keras.ops.take · where · clip · argmax · top_k
    Indexing and selection.
  • keras.ops.vectorized_map(fn, elems)
    Batch a per-example function instead of looping it.
04Tensors, variables & RNGstate, portably
  • keras.Variable(initializer, shape, trainable=True)★
    The backend-neutral variable. On torch it wraps a parameter; on TF a tf.Variable.
  • v.assign(x) · v.value
    Mutation goes through assign, never rebinding the name.
  • keras.random.normal(shape, seed=seed)
    Stateless. Pass a seed or a SeedGenerator — this is what makes custom layers work on JAX.
  • self.seed_generator = keras.random.SeedGenerator(1337)
    Create it in __init__, then pass it as seed= inside call.
  • keras.utils.set_random_seed(42)
    Seeds Python, NumPy and the backend in one call.
  • a Python RNG inside a layer★
    Breaks on JAX, and silently produces the same numbers under tracing. Use keras.random.
  • keras.Variable(..., dtype=, aggregation=)
    Dtype and multi-replica aggregation are set at construction.
  • keras.config.floatx()
    What new variables default to. Change it globally rather than casting everywhere.
05Three ways to buildpick the simplest that fits
  • keras.Sequential([...])★
    A straight stack. Enough more often than people admit.
  • inp = keras.Input(shape=(32,)); out = Dense(1)(inp)★
    The Functional API — any DAG, with shapes checked as you wire it.
  • model = keras.Model(inp, out)★
    Close the graph by naming its ends.
  • class Net(keras.Model): call(self, x, training=None)
    Subclassing. Maximum freedom, no static graph to inspect.
  • keras.Model(inputs=[a,b], outputs={"cls": y1, "reg": y2})
    Multiple inputs and outputs, with dict losses in compile.
  • model.summary() · keras.utils.plot_model(model, show_shapes=True)
    Empty until the model is built — call it on data first, or pass an Input.
  • keras.Model(model.inputs, model.get_layer(n).output)
    Feature extraction from a trained network, in one line.
  • Input(shape=(32,))shape
    No batch dimension. Passing (None, 32) is the classic first mistake.
  • a Model is a Layer
    So you can nest a whole model inside another as a single layer, and share it across branches.
  • model.layers · model.inputs · model.outputs
    Introspection on Functional models; sparse on subclassed ones.
06Layersthe catalogue
  • Dense(128, activation="relu")★
    Units first; input size inferred.
  • Conv2D(32, 3, padding="same") · Conv1D · Conv3D★
    Channels-last by default on every backend.
  • MaxPooling2D · GlobalAveragePooling2D · Flatten
    Downsample and collapse.
  • BatchNormalization · LayerNormalization · GroupNormalization
    Normalization family.
  • Dropout(0.5) · SpatialDropout2D · GaussianNoise
    Regularization by noise.
  • Embedding(vocab, dim, mask_zero=True) · LSTM · GRU · Bidirectional★
    Sequence basics. mask_zero propagates a padding mask.
  • MultiHeadAttention(num_heads=8, key_dim=64)
    Transformer attention, built in.
  • Add · Concatenate · Lambda(fn) · Identity
    Merges and escape hatches.
  • keras.activations · activation= on the layer
    Either as a string, a function, or a separate Activation layer.
  • Attention · AdditiveAttention · GroupQueryAttention
    The rest of the attention family.
  • TimeDistributed(layer) · RepeatVector · Cropping2D
    Apply per timestep; broadcast along time; trim spatial edges.
  • return_sequences= · return_state= · stateful=
    RNN switches. return_sequences gives every step; stateful carries state across batches and needs a fixed batch size.
  • out = (in + 2*pad − k) // stride + 1
    The conv size formula. padding="same" preserves size at stride 1.
07Write your own layerthe extension point
  • class MyLayer(keras.layers.Layer):★
    Everything — including Model — is a Layer. Learn this once.
  • build(self, input_shape)★
    Where weights are created, once, when the real input shape is known.
  • self.w = self.add_weight(shape=..., initializer=..., trainable=True)
    Registers the variable so Keras tracks, saves and trains it.
  • call(self, inputs, training=None)
    The forward pass. Honour training if behaviour differs while fitting.
  • use keras.ops inside call
    The difference between a portable layer and a TensorFlow-only one.
  • get_config(self)
    Without it the layer cannot be reloaded. Return every constructor argument.
  • @keras.saving.register_keras_serializable()
    Lets load_model find your class with no custom_objects dict.
  • self.add_loss(v) · self.compute_output_shape(s)
    Attach a regularization term; declare a shape Keras cannot infer.
  • creating weights in __init__★
    Only works if you already know the input shape. build exists to avoid that.
  • self.built = True at the end of build
    Keras sets it for you when you subclass properly; set it yourself only in unusual builds.
  • from_config(cls, config)
    The other half of serialization — needed when a constructor argument is itself an object.
  • a custom Model is just a Layer with fit
    Everything in card 12 applies to it unchanged.
08Losses, metrics, optimizersthe training contract
  • keras.losses.SparseCategoricalCrossentropy(from_logits=True)★
    Integer labels. The most common classification loss.
  • from_logits=True ↔ no final activation★pair up
    Pair them. A softmax layer plus from_logits=True trains on nonsense and never errors.
  • keras.losses.BinaryCrossentropy · MeanSquaredError · Huber
    Binary, regression, robust regression.
  • label_smoothing=0.1
    Softens hard targets; cheap and reliably helps calibration.
  • keras.optimizers.AdamW(learning_rate=1e-3, weight_decay=0.01)★
    Decoupled decay — the modern default.
  • clipnorm=1.0 · clipvalue=
    Gradient clipping lives on the optimizer, not in the loop.
  • opt.exclude_from_weight_decay(var_names=["bias", "scale"])
    Standard for transformers.
  • class M(keras.metrics.Metric): update_state / result / reset_state
    The three methods a stateful metric implements.
  • loss_fn(y_true, y_pred)
    True first — the opposite order to several other libraries.
  • keras.metrics.Mean(name="loss") · SparseCategoricalAccuracy · AUC · F1Score
    The stateful metric catalogue.
  • keras.losses.CategoricalFocalCrossentropy(gamma=2.0)
    Down-weights easy examples — the standard answer to heavy imbalance.
  • keras.optimizers.Lion · Adafactor · SGD(momentum=0.9, nesterov=True)
    Memory-lean alternatives, and the classic that still wins on vision.
  • loss=[...] or loss={...} with loss_weights=
    Per-output losses for multi-head models, keyed by output name.
09Learning-rate schedulesthe highest-leverage knob
  • keras.optimizers.schedules.CosineDecay(lr, decay_steps)★
    Pass the schedule object as learning_rate=, not a float. The optimizer steps it for you.
  • CosineDecay(lr, steps, warmup_target=lr, warmup_steps=500)★
    Warmup and decay in one object — what almost every transformer recipe wants.
  • ExponentialDecay · PiecewiseConstantDecay · InverseTimeDecay
    The classics, still fine for vision.
  • decay_steps = steps_per_epoch * epochs★units
    Counted in steps, not epochs. Getting this wrong decays to zero a tenth of the way in, or never decays at all.
  • keras.callbacks.ReduceLROnPlateau(factor=0.5, patience=3)
    The reactive alternative. Do not combine it with a schedule object — they fight.
  • keras.callbacks.LearningRateScheduler(fn)
    A plain function of epoch number, when you want full control.
  • log it: opt.learning_rate
    A schedule that is not doing what you think is a common and invisible bug.
10compile() & fit()the loop, for free
  • model.compile(optimizer=, loss=, metrics=[])★
    Strings work: "adam", "mse", "accuracy".
  • model.fit(data, epochs=10, validation_data=val)★
    data can be almost anything — arrays, tf.data, a torch DataLoader, a PyDataset.
  • validation_split=0.2
    Arrays only. It cannot split a dataset or a loader.
  • history.history["val_loss"]
    Everything for your learning curves.
  • model.evaluate(test) · model.predict(x)
    predict loops a dataset and returns NumPy; model(x) is faster for one batch.
  • class_weight= · sample_weight=
    Imbalance, without touching the data.
  • steps_per_epoch= · validation_steps=
    Required for infinite datasets.
  • jit_compile=True
    Compiles the step where the backend supports it.
  • model.fit(..., verbose=2)
    One line per epoch — what you want in a log file rather than a terminal.
  • initial_epoch=n · validation_freq=
    Resume with honest epoch numbering; validate less often when it dominates.
  • model.predict_on_batch(x) · model.train_on_batch(x, y)
    Single-batch calls, for reinforcement learning and other manual loops.
  • fit() on a generator that never ends★
    Without steps_per_epoch the first epoch never finishes.
11Callbackshooks into fit()
  • keras.callbacks.ModelCheckpoint("best.keras", save_best_only=True)★
    Keep the best epoch, not the last.
  • keras.callbacks.EarlyStopping(patience=5, restore_best_weights=True)★
    Set restore_best_weights or you keep the worse, later weights.
  • keras.callbacks.ReduceLROnPlateau(factor=0.5, patience=3)
    Cut the learning rate when validation stalls.
  • keras.callbacks.TensorBoard(log_dir="logs")
    Works on every backend. pip install tensorboard separately.
  • keras.callbacks.BackupAndRestore · CSVLogger · TerminateOnNaN
    Resume after a crash; log to file; bail on NaN.
  • class Cb(keras.callbacks.Callback): on_epoch_end(self, epoch, logs)
    Your own. self.model.stop_training = True ends the run.
  • logging is async in fit()3.6+
    Custom callbacks relying on on_batch_end disable it; set self.async_safe = True if yours is safe.
  • keras.callbacks.SwapEMAWeights(swap_on_epoch=True)3.x
    Evaluate with the exponential moving average of the weights — often a free accuracy gain.
  • logs is a dict you may mutate
    Adding a key in on_epoch_end makes it visible to every later callback, including checkpointing.
  • order matters★
    Callbacks fire in list order; put anything that writes logs before the callback that reads it.
12Custom trainingfrom train_step to raw loops
  • model.train_step(self, data)★
    The middle path — override one method, keep fit() with all its callbacks.
  • self.compute_loss(x, y, y_pred, sample_weight)★
    Override this instead and your customization stays backend-agnostic.
  • self.test_step · self.predict_step
    The evaluation and inference counterparts.
  • a fully custom loop is backend-specific★not portable
    There is no portable raw loop. Gradients come from GradientTape, loss.backward() or jax.grad — see Parts III and IV.
  • model.trainable_weights · model.get_state_tree()
    The variables, and a nested path→value dict useful for JAX loops.
  • metric.update_state() → result() → reset_state()
    Reset each epoch or you average across all of training.
  • keras.Model(..., jit_compile=)
    Where supported, compiles your custom step too.
  • @keras.saving.register_keras_serializable() on a custom Model
    Otherwise the subclass cannot be reloaded, exactly as with layers.
  • self.compute_metrics(x, y, y_pred, sample_weight)
    The metrics counterpart of compute_loss; also portable.
  • self.metrics must list your trackers
    Return them from the metrics property or fit() will not reset them between epochs.
13Debug & inspectbefore blaming the model
  • model.summary(expand_nested=True, show_trainable=True)★
    Shows which layers are frozen — the fastest way to catch a fine-tuning mistake.
  • model.compile(..., run_eagerly=True)
    Turns off compilation so you can put a breakpoint or a print inside a custom step.
  • overfit a single batch first
    If the model cannot drive one batch to near-zero loss, the bug is in the model or the loss — not the data.
  • keras.utils.set_random_seed(42)
    Python, NumPy and the backend in one call.
  • print(x.shape, x.dtype) · keras.ops.shape(x)
    Nearly every error is a shape or a dtype disagreeing.
  • layer.weights · layer.trainable_weights · layer.losses
    What the layer owns, what will be updated, and what it contributes to the loss.
  • loss is NaN from step one★
    Learning rate too high, unscaled inputs, or a log(0). Check inputs before architecture.
  • val metrics stuck at chance★
    Almost always the from_logits mismatch, or labels misaligned with predictions.
  • "You must call build() first"
    The model has not seen data. Pass an Input, or call it on one batch before summary().
14Save, load & serializethree different files
  • model.save("m.keras")★Keras 3
    The extension is mandatory. A bare path raises ValueError: Invalid filepath extension.
  • keras.saving.load_model("m.keras")★
    Architecture, weights and optimizer state — ready to resume.
  • model.save_weights("m.weights.h5")
    Weights only; that exact suffix is required.
  • model.load_weights(path, skip_mismatch=True)
    Partial restore when the architecture has drifted.
  • custom_objects={...} or @register_keras_serializable
    Custom layers and losses must be findable or the load fails.
  • keras.saving.KerasFileEditor(path)3.6+
    Inspect, diff, edit and resave a weights file without loading the model.
  • the .keras file is a zip
    Config JSON plus weights. You can open it and look.
  • loading an untrusted .h5★security
    Keras 3.12.3 was a security release hardening exactly this — HDF5 links and virtual datasets could read arbitrary files. Prefer .keras, and never load files you did not produce.
  • keras.saving.serialize_keras_object / deserialize_keras_object
    The pair underneath everything; useful when nesting objects in a config.
  • model.save_own_variables / load_own_variables
    Override to control exactly what a custom layer persists.
  • Orbax checkpointing
    On JAX, the standard async/distributed checkpoint format — a separate guide in the Keras docs.
15Export & deployout of Python
  • model.export("saved_model/")★Keras 3
    This is how you get a SavedModel. save() no longer produces one.
  • model.export(path, format="tf_lite")3.13+
    Direct LiteRT export for on-device inference.
  • model.export(path, format="onnx")
    ONNX for runtimes that speak it.
  • keras.export.ExportArchive()
    Fine control — multiple endpoints and custom signatures.
  • keras.layers.TFSMLayer(path, call_endpoint="serving_default")★
    Read a SavedModel back as a layer. Inference only.
  • load_model("saved_model/")★Keras 3
    Cannot load a SavedModel. Keras 3 reads only .keras and .h5.
  • export works from any backend
    A model trained on PyTorch can still be exported for TF Serving.
  • export needs TensorFlow installeddependency
    Even from a torch or JAX model — the SavedModel writer is TF's.
  • archive = keras.export.ExportArchive(); archive.add_endpoint(...)
    Several named signatures in one artifact, each with its own input spec.
  • test the export, not the model
    Reload with TFSMLayer and compare outputs before shipping. Preprocessing baked into the graph is easy to get wrong.
16Quantization & LoRAmaking big models fit
  • model.quantize("int8")★Keras 3
    Post-training quantization in one call, on the Keras model itself.
  • quantize("int4") · "gptq" · "awq"
    Lower precision and the calibration-based schemes, each with its own guide.
  • backbone.enable_lora(rank=4)★
    Freezes the weights and adds small trainable adapters to the attention projections.
  • quantize("int8") then enable_lora(rank=4)
    That order is QLoRA. The adapters must stay in full precision.
  • keras.mixed_precision.set_global_policy("mixed_float16")
    One line, roughly 2× on modern GPUs.
  • final layer dtype="float32"
    With mixed precision, force the output back to float32 for numerical safety.
  • keras.distribution.DataParallel() · ModelParallel()
    The backend-agnostic sharding API.
  • quantize after training, then evaluate
    Always re-measure. int8 is usually near-free; int4 rarely is.
  • LoRA weights merge on save
    Saving a LoRA model writes merged weights, so the deployed artifact needs no adapter machinery.
  • keras.distribution.set_distribution(...) · DeviceMesh · LayoutMap
    The sharding vocabulary: a mesh of devices and a map from variable paths to layouts.
  • keras.distribution is JAX-first★
    On TensorFlow use tf.distribute; on torch use DDP. The unified API does not yet cover them.
17KerasTunersearching the space
  • pip install keras-tuner · import keras_tuner★
    A separate package, and backend-agnostic like the rest of Keras 3.
  • def build_model(hp): … return model★
    The whole interface. A function that builds and compiles a model, taking an hp object.
  • hp.Int("units", 32, 512, step=32) · hp.Choice · hp.Boolean
    Declare a hyperparameter where you would have written a constant.
  • hp.Float("lr", 1e-4, 1e-2, sampling="log")
    Log sampling for learning rates. Linear sampling wastes most trials at the top of the range.
  • tuner = keras_tuner.RandomSearch(build_model, objective="val_loss", max_trials=20)
    Also Hyperband, BayesianOptimization and Sklearn.
  • tuner.search(x, y, epochs=5, validation_data=val)
    Same signature as fit() — callbacks included.
  • tuner.get_best_hyperparameters()[0] · get_best_models()
    Then rebuild and retrain properly on the full data.
  • executions_per_trial=2
    Averages over repeats to stop noise winning the search.
  • directory= and project_name= resume silently★
    A rerun with the same names continues the old study rather than starting fresh.

    The portable dataset. Works on every backend, with workers= and use_multiprocessing=.
  • keras.utils.image_dataset_from_directory(path, image_size=(224,224))★
    Folder of class subfolders straight to a batched dataset.
  • keras.utils.text_dataset_from_directory · audio_dataset_from_directory
    The same idea for text and audio.
  • keras.utils.timeseries_dataset_from_array(data, targets, sequence_length=24)
    Sliding windows with targets aligned.
  • keras.utils.split_dataset(ds, left_size=0.8)

  • keras.utils.get_file(fname, origin=url, extract=True)

  • keras.utils.to_categorical · normalize · pad_sequences

  • keras.utils.split_dataset · image_dataset_from_directory(subset="both", validation_split=0.2, seed=)leak

19Preprocessing layersthe modern way
  • keras.layers.Rescaling(1./255)★
    The one-liner every image model starts with.
  • keras.layers.Normalization(); layer.adapt(data)★
    Learns statistics from data, then travels with the saved model. No train/serve skew.
  • keras.layers.RandomFlip · RandomRotation · RandomZoom · RandomTranslation★
    Augmentation layers — active in training, bypassed at inference automatically.
  • keras.layers.TextVectorization(max_tokens=20000); .adapt(texts)
    Builds the vocabulary, then maps strings to integer sequences.
  • keras.layers.StringLookup · IntegerLookup · Discretization · Hashing
    Categorical encoding, binning and hashing.
  • keras.layers.Resizing · CenterCrop · AutoContrast
    Deterministic image shaping.
  • in the pipeline, or in the model?
    In a map they run on CPU in parallel; inside the model they run on GPU and ship with the export.
  • layer.adapt(ds.map(lambda x, y: x))
    Adapt on features only. Passing (x, y) is a common and confusing failure.
  • keras.layers.Pipeline([...])
    Chains preprocessing layers into one reusable object.
  • some preprocessing layers need TensorFlowdependency
    TextVectorization and friends depend on TF ops even on other backends. Install it.
  • call adapt() once, then save the model
    The learned vocabulary or statistics travel inside the artifact — the whole point.
20Pretrained modelsapplications & KerasHub
  • base = keras.applications.ResNet50(weights="imagenet")★
    Built in, no extra install. Classic vision classifiers and feature extractors.
  • ResNet50(include_top=False, pooling="avg")★
    Drop the classifier head and get an embedding — the usual starting point.
  • keras.applications.resnet50.preprocess_input(x)★per-family
    Each family has its own. Using the wrong one silently costs accuracy.
  • EfficientNetV2B0 · ConvNeXtTiny · MobileNetV3Small
    Stronger and lighter than ResNet50 for most new work. EfficientNetV2 takes raw 0–255 input.
  • pip install keras-hub
    The modern, wider option — text, vision and multimodal presets behind one constructor.
  • keras_hub.models.TextClassifier.from_preset("bert_base_en", num_classes=2)
    Downloads config, weights and preprocessing together, and fits on raw strings.
  • keras_hub.models.CausalLM.from_preset("gemma_2b_en")
    Generative models, with .generate(); pair with LoRA from card 16.
  • applications or KerasHub?
    Applications for a quick classifier or feature extractor; KerasHub for detection, segmentation, text and anything new.
21Transfer learningthe recipe, in order
  • base.trainable = False★
    Step one: freeze. Train the new head first, or large random-head gradients wreck the pretrained weights.
  • x = base(inputs, training=False)★subtle
    Pass this too. Freezing does not stop BatchNorm updating its running statistics; this does.
  • x = GlobalAveragePooling2D()(x); out = Dense(n)(x)
    The new head. Train it to convergence at a normal learning rate.
  • base.trainable = True; model.compile(optimizer=AdamW(1e-5))
    Step two: unfreeze and recompile, at 10–100× lower learning rate.
  • forgetting to recompile after unfreezing★silent
    The change does not take effect — trainable is read at compile time. Nothing warns you.
  • for layer in base.layers[:-20]: layer.trainable = False
    Partial unfreezing — the last few blocks only, when data is scarce.
  • model.summary(show_trainable=True)
    Verify the freeze actually took before spending a GPU hour.
  • match the preprocessing to the backbone
    Each expects its own input range. This is the quietest way to lose several points of accuracy.
22Migrating Keras 2 → 3what actually changes
  • on TensorFlow, most code just runs★
    Keras 3 is a drop-in replacement for tf.keras. Update save() to the .keras format and you are usually done.
  • three tasks make it backend-agnostic
    Replace tf.* with keras.ops.*; port custom train_step/test_step; use stateless keras.random. That is the official list.
  • tf.math.* · tf.linalg.* → keras.ops.*
    Names mostly match one-to-one; the few that differ are called out in the migration guide.
  • keras.backend.* is largely gone★Keras 3
    backend.function, learning_phase and the symbolic helpers no longer exist. Use keras.ops.
  • saving changed★
    save("path") raises — use .keras; SavedModel now comes from export(); weights need .weights.h5.
  • removed odds and ends
    keras.constraints.RadialConstraint and other low-usage symbols were dropped outright.
  • nested-structure inputs are stricter
    Keras 3 validates structures more carefully; a model fed a list where it declared a dict now errors instead of guessing.
  • if it will not port, pin Keras 2
    pip install tf-keras and the legacy flag — see the Part III card.
23The JAX backendbriefly, for completeness
  • os.environ["KERAS_BACKEND"] = "jax"★
    Often the fastest option, and the only one with first-class TPU support.
  • pip install "jax[cuda12]" · jax[tpu]
    The accelerator build matters more here than on the other backends.
  • everything must be stateless★
    JAX traces pure functions. This is why keras.random takes a seed and why variables are updated through explicit state.
  • a JAX train_step takes and returns state
    (trainable_vars, non_trainable_vars, optimizer_vars) in, updated values out — unlike TF and torch, which mutate in place.
  • model.stateless_call(tv, ntv, x) · model.get_state_tree()
    The plumbing for a hand-written JAX loop.
  • keras.distribution targets JAX first
    DeviceMesh, LayoutMap and model parallelism are most complete here.
  • Orbax for checkpoints · NNX interop
    The JAX-native checkpoint format, and a guide for using Keras with Flax NNX.
  • a Python side effect inside a layer★
    Printing, appending to a list, or mutating an attribute in call happens once at trace time and then never again.
PART II

keras-preprocessing  ·  the archived module

Read this before copying any tutorial. The standalone package's final release was 1.1.2 in May 2020 — declaring support for Python 2.7–3.6 — and the repository was archived in September 2024. Its symbols moved into core Keras, were deprecated there, and in Keras 3 survive only under the private keras._legacy.preprocessing namespace. This part covers what each symbol became.
K1Where it standsthe honest status
  • final release 1.1.2, May 2020
    Six years without a release. The wheel still installs; nothing is maintained.
  • repository archived Sep 2024★archived
    Read-only. The README already redirected all work to core Keras years earlier.
  • declares Python 2.7–3.6★
    Keras 3 requires Python 3.11+. The version ranges no longer even overlap.
  • keras._legacy.preprocessing.image.ImageDataGenerator
    Where it lives in Keras 3 — a private namespace, with a docstring that reads simply DEPRECATED.
  • you almost never need to install it
    TensorFlow used to pull it in as a dependency. Modern installs do not.
  • still fine for
    Reproducing an old result exactly, or reading code written before 2022.
  • check before you debug★
    If a traceback mentions keras.preprocessing or keras_preprocessing, you are running pre-2022 code. Port it rather than patching it.
K2The image APIImageDataGenerator → layers
  • ImageDataGenerator(rescale=1./255, rotation_range=20)★
    The Keras 2 workhorse. CPU-bound, NumPy-based, and no longer the recommended path.
  • keras.utils.image_dataset_from_directory(dir, image_size=, batch_size=)
    Replaces flow_from_directory. Same folder convention, a real dataset out.
  • keras.layers.Rescaling(1./255)
    Replaces rescale=.
  • keras.layers.RandomRotation · RandomZoom · RandomFlip · RandomTranslation
    Replace rotation_range, zoom_range, horizontal_flip, width/height_shift_range.
  • why it changed
    Layers run on the GPU, inside the model, and are exported with it. Generators ran on CPU and had to be reimplemented at serving time.
  • flow_from_dataframe has no direct replacement
    Build a dataset from the dataframe columns yourself — paths in, decode in a map.
  • shear_range has no built-in layer★real gap
    A genuine gap, and an open complaint upstream. Write a custom layer or use a third-party augmentation library.
  • keras.layers.RandomBrightness · RandomContrast · RandomSharpness
    Photometric augmentation the old generator never had.
  • validation_split in ImageDataGenerator → subset="both"★
    image_dataset_from_directory does the same job — but you must pass the same seed to both calls.
K3The text APITokenizer → TextVectorization
  • Tokenizer(num_words=20000); .fit_on_texts(texts)★
    The Keras 2 text pipeline: fit, then texts_to_sequences, then pad.
  • vec = keras.layers.TextVectorization(max_tokens=20000)★
    The replacement, and it is a layer. Standardize, split, index and pad in one object.
  • vec.adapt(texts)
    Replaces fit_on_texts. Builds the vocabulary from data.
  • output_sequence_length=128 · output_mode="int" | "tf_idf"
    Padding and truncation are settings, not a separate step.
  • vec.get_vocabulary()
    Replaces tokenizer.word_index. Index 0 is padding, 1 is OOV.
  • put the layer inside the model
    Then raw strings go in at serving time and the vocabulary cannot drift.
  • one_hot · hashing_trick · text_to_word_sequence
    Legacy helpers. Use keras.layers.Hashing and the vectorizer's own standardization.
  • standardize= · split= · ngrams=
    The knobs that replace the old filters, lower and manual n-gram code.
  • a pickled Tokenizer cannot be loaded into TextVectorization★
    Re-adapt on the original corpus, or set the vocabulary explicitly with set_vocabulary().
K4The sequence APIgenerators → functions
  • TimeseriesGenerator(data, targets, length=)★removed
    Removed from the public API.
  • keras.utils.timeseries_dataset_from_array(data, targets, sequence_length=)
    The replacement. A function returning a dataset, not a stateful generator class.
  • sequence_stride= · sampling_rate= · shuffle=
    Step between windows, gap within a window, and shuffling after windowing.
  • keras.utils.pad_sequences(seqs, maxlen=, padding="post")
    This one survived into keras.utils and is still the right call.
  • Sequence → keras.utils.PyDataset★
    The base class for custom generators was renamed. Same two methods, new name and better multiprocessing.
  • skipgrams · make_sampling_table
    Word2vec-era helpers, gone. Use KerasHub or write the sampling yourself.
K5Rebuilding an old pipelinebefore and after
  • gen = ImageDataGenerator(rescale=1./255, rotation_range=20, horizontal_flip=True)★
    Before. One object doing loading, rescaling and augmentation on the CPU.
  • gen.flow_from_directory(dir, target_size=(224,224), batch_size=32)
    And one call producing an infinite generator.
  • ds = keras.utils.image_dataset_from_directory(dir, image_size=(224,224), batch_size=32)
    After, step one: loading only. Same folder layout, so no data moves.
  • aug = keras.Sequential([Rescaling(1./255), RandomRotation(0.06), RandomFlip("horizontal")])units
    Step two: augmentation as layers. Rotation is now a fraction of 2π, not degrees.
  • model = keras.Sequential([aug, base_model, head])
    Step three: put it in the model. It runs on the GPU and exports with the artifact.
  • or ds.map(lambda x, y: (aug(x, training=True), y))
    The alternative — augment in the pipeline on CPU, in parallel with training.
  • steps_per_epoch is no longer needed★
    The old generator was infinite; a dataset is finite and fit() just consumes it.
  • rotation_range=20 ≠ RandomRotation(20)★classic
    Degrees versus a fraction of a full turn. 20/360 ≈ 0.056 — passing 20 rotates wildly.
K6Migration mapold call → new call
  • ImageDataGenerator → image_dataset_from_directory + Random* layers★
    Two objects instead of one, and both faster.
  • flow_from_directory → image_dataset_from_directory★
    Same directory layout, so no data reorganisation needed.
  • Tokenizer → keras.layers.TextVectorization★
    And it can live inside the model.
  • TimeseriesGenerator → utils.timeseries_dataset_from_array
    Function, not class.
  • Sequence → utils.PyDataset
    Rename plus workers= and use_multiprocessing=.
  • load_img / img_to_array → utils.load_img / img_to_array
    These kept their names inside keras.utils.
  • pad_sequences → unchanged, in utils
    One of the few symbols to survive intact.
  • preprocessing_function= → write a Layer
    Arbitrary per-sample Python becomes a custom layer, or a step in your data pipeline.
PART III

keras + tensorflow  ·  the default pairing

Since TF 2.16, pip install tensorflow brings Keras 3 and tf.keras is Keras 3. This is the backend with the most mature serving story — tf.data, SavedModel, TF Serving, tf.distribute — and the one where reaching for tf.* inside a custom layer costs you portability without any warning.
T1Setup on TensorFlowgains and trade-offs
  • pip install tensorflow★
    Brings Keras 3 since TF 2.16. TensorBoard is separate since 2.21.
  • os.environ["KERAS_BACKEND"] = "tensorflow"
    The default when TF is the only backend installed.
  • import keras vs from tensorflow import keras
    Same object on TF 2.16+. Prefer plain import keras — it keeps you honest about which Keras you are on.
  • what you gain
    tf.data, SavedModel export, TF Serving, TPU via tf.distribute, and the largest body of existing code.
  • what you lose by using it carelessly★portability
    Any tf.* call inside a custom layer silently pins that layer to this backend.
  • tf.config.experimental.set_memory_growth(gpu, True)
    TF grabs the whole GPU at startup otherwise. Set it before anything runs.
T2tf.data with Kerasthe input pipeline
  • ds = tf.data.Dataset.from_tensor_slices((X, y))★
    Then pass it straight to fit().
  • ds.shuffle(1024).batch(32).prefetch(AUTOTUNE)
    Shuffle before batch; prefetch last. The two rules that matter.
  • ds.map(fn, num_parallel_calls=tf.data.AUTOTUNE)
    Without AUTOTUNE the map is single-threaded.
  • ds.cache()
    After expensive deterministic work, before random augmentation.
  • preprocessing layers work inside map
    They are callable on tensors, so you can run them on CPU in the pipeline instead of on GPU in the model.
  • a tf.data pipeline is not portable★
    It will feed a torch- or JAX-backed Keras model, but it drags TensorFlow into your dependencies.
  • ds.cache().shuffle(n).batch(b).prefetch(AUTOTUNE)
    Cache after expensive deterministic work, before random augmentation.
  • tf.data works on every backend★
    It just drags TensorFlow into the dependency list — which you likely need anyway for preprocessing layers.
T3TF-native trainingwhen you drop down
  • with tf.GradientTape() as tape: loss = loss_fn(y, model(x, training=True))★
    The TF way to write a raw loop around a Keras model.
  • grads = tape.gradient(loss, model.trainable_weights)
    No zero_grad — a fresh tape never accumulates.
  • opt.apply_gradients(zip(grads, model.trainable_weights))
    And the step is done.
  • @tf.function
    Decorate the step, not the epoch loop. That is most of the speed.
  • strategy = tf.distribute.MirroredStrategy()
    Multi-GPU. Build and compile inside strategy.scope() or the variables are not mirrored.
  • a TF custom train_step will not run on torch★
    It is the clearest example of the portability trade-off — override compute_loss instead where you can.
T4Graph mode & tf.functionwhat Keras hides
  • fit() already traces your step★
    Keras compiles the training step for you. @tf.function around your own loop is what you add manually.
  • model.compile(..., run_eagerly=True)
    Turns tracing off for one model so you can debug inside a custom step.
  • model.compile(..., jit_compile=True)
    Hands the step to XLA. Often a solid win, sometimes a long compile.
  • print() inside a traced step fires once★
    It runs at trace time. tf.print becomes a graph op and fires every call.
  • retracing on every new shape★
    A last partial batch, or Python ints passed as arguments, triggers a fresh trace. Watch for the retracing warning.
  • tf.function(reduce_retracing=True)
    The blunt fix when shapes genuinely vary.
  • a Python loop over a tensor unrolls
    Into the graph, once per iteration. Vectorise, or use keras.ops.while_loop.
T5Export & servingthe TF advantage
  • model.export("saved_model/")★
    The SavedModel directory TF Serving expects.
  • docker run -p 8501:8501 tensorflow/serving★
    Point it at the exported directory and you have a REST endpoint.
  • keras.layers.TFSMLayer(path, call_endpoint="serving_default")
    Load a SavedModel back into Keras 3 as an inference-only layer.
  • saved_model_cli show --dir path --all
    Inspect signatures before trying to serve them.
  • model.export(path, format="tf_lite")LiteRT
    On-device. tf.lite itself is deprecated in favour of LiteRT.
  • preprocessing layers export with the model
    The main practical reason to put Normalization and TextVectorization inside the model.
  • check the signature before serving
    saved_model_cli show --dir path --all, or reload with TFSMLayer and compare outputs.
T6The Keras 2 escape hatchwhen you must go back
  • pip install tf-keras★
    Keras 2, still released (2.21.0, Mar 2026) alongside Keras 3.
  • os.environ["TF_USE_LEGACY_KERAS"] = "1"
    Points tf.keras back at Keras 2. Set before importing TensorFlow.
  • import tf_keras as keras
    Or import it explicitly and leave tf.keras alone.
  • when you actually need this
    Old checkpoints, hub.KerasLayer, TensorFlow Addons, or a plugin never ported to Keras 3.
  • the legacy flag is global★
    The whole environment reverts to Keras 2, including libraries that expect 3.
  • estimator-era code is simply gone
    tf.estimator was removed in TF 2.16 and no flag brings it back.
PART IV

keras + pytorch  ·  two-way interop

The most surprising part of Keras 3: on the torch backend a Keras layer is a torch.nn.Module. Not wrapped, not adapted — it subclasses it. So Keras layers drop into PyTorch models and register their parameters, PyTorch modules drop into Keras models as layers, and fit() accepts a DataLoader. You can adopt as much or as little of either as you like.
P1Setup on PyTorchgains and trade-offs
  • os.environ["KERAS_BACKEND"] = "torch"; import keras★
    That is the entire switch.
  • pip install torch keras
    No TensorFlow required anywhere in the stack.
  • a Keras model is an nn.Module
    The fact everything else follows from. .parameters(), .to(device) and state_dict() all work.
  • model.fit(dataloader, epochs=5)
    A torch.utils.data.DataLoader is a first-class input to fit.
  • device placement is torch's
    Keras does not manage devices here; move things with .to("cuda") as usual.
  • no tf.data, no SavedModel by default★
    You still get .keras saving, and export() works if TensorFlow happens to be installed.
P2Data with DataLoadertorch-native input
  • loader = torch.utils.data.DataLoader(ds, batch_size=32, shuffle=True)★
    Your existing Dataset and DataLoader carry over untouched.
  • model.fit(loader, validation_data=val_loader)★
    Keras reads batches from the loader and runs its own loop, callbacks and metrics.
  • the batch must be (x, y) or (x, y, sample_weight)
    A loader yielding a dict or a custom object needs a collate_fn that produces that tuple.
  • keras.utils.PyDataset also works
    If you want one data class that runs on every backend, use this instead of a DataLoader.
  • num_workers and Keras callbacks
    Standard torch multiprocessing caveats apply — workers on Windows and notebooks are the usual pain.
  • pin_memory=True · num_workers=4 · persistent_workers=True
    Standard DataLoader throughput settings; Keras changes none of them.
P3Layers both waysthe interop
  • class Net(torch.nn.Module): self.fc = keras.layers.Dense(64)★
    A Keras layer inside a torch Module. Its weights appear in net.parameters() automatically.
  • opt = torch.optim.Adam(net.parameters(), lr=1e-3)
    So a plain torch optimizer trains Keras layers with no adapter.
  • keras.Sequential([..., MyTorchModule(), ...])
    And the other direction — a torch Module used as a Keras layer.
  • build lazily or eagerly
    Keras layers infer input shape on first call; torch modules want it declared. Mixing means being explicit about which is which.
  • a Keras layer only becomes an nn.Module on the torch backend★torch only
    The same code on JAX gives you something else entirely. This interop is backend-specific by definition.
  • why it matters
    You can adopt Keras incrementally inside a PyTorch codebase, one layer at a time, with nothing to rewrite.
P4A native torch loopfull manual control
  • model = get_model(); opt = torch.optim.Adam(model.parameters(), lr=1e-3)★
    A Keras model, a torch optimizer. No bridge needed.
  • loss_fn = torch.nn.CrossEntropyLoss()
    A torch loss, or a keras.losses one — both work.
  • model.zero_grad()★required
    Before backward(), every step. This is torch semantics: gradients accumulate.
  • loss.backward(); opt.step()
    Standard PyTorch from here on.
  • logits = model(x, training=True)
    Keep the Keras kwarg — it is what switches Dropout and BatchNorm, not model.train().
  • override train_step instead
    Custom logic while keeping fit(): call zero_grad(), compute via self.compute_loss(), then backward().
  • forgetting zero_grad()★
    Gradients silently accumulate across steps and the model diverges. The single most common torch-backend bug.
P5The torch ecosystemwhat else carries over
  • torch.compile(model)★
    Works, because the model is an nn.Module. Compile before training; expect a slow first step.
  • model.state_dict() · model.load_state_dict(sd)
    Torch-native checkpointing of a Keras model. Useful for interop; .keras is still the portable format.
  • with torch.autocast("cuda", dtype=torch.bfloat16):
    Torch AMP in a hand-written loop. With fit(), prefer keras.mixed_precision instead.
  • do not stack both mixed-precision systems★conflict
    A Keras global policy plus torch.autocast is double-casting. Pick one.
  • torchvision.transforms in your Dataset
    Perfectly fine — but those transforms will not export with the model, unlike Keras preprocessing layers.
  • torch.profiler · TensorBoard
    The torch profiler works unchanged; the Keras TensorBoard callback also works.
  • model.parameters() · .named_parameters()
    Everything downstream — optimizers, schedulers, gradient clipping, EMA — sees ordinary parameters.
  • model.train() / .eval() are not the switch★classic
    Keras honours the training= kwarg. Setting torch's module mode alone does not toggle Dropout or BatchNorm here.
P6Multi-GPU with DDPscaling out
  • torch.distributed.init_process_group(...) + torch.cuda.set_device(rank)★
    Standard torch setup, per process.
  • DistributedSampler + DataLoader★
    Shards the data across ranks.
  • torch.nn.parallel.DistributedDataParallel(model)
    Wraps the Keras model directly, because it is already an nn.Module.
  • then train as normal
    Either fit() or your own loop, launched once per device.
  • keras.distribution is JAX-first today
    For torch, use DDP; the backend-agnostic distribution API does not cover it yet.
  • checkpoint from rank 0 only
    Otherwise every process writes the same file at once.
  • torchrun --nproc_per_node=4 train.py
    The usual launcher. Keras needs no special entry point.

Four pictures worth the whole reference

What each backend gives you, where preprocessing went, how the PyTorch interop works, and which file to save.

1 · choosing a backend

The same model runs on all four. What differs is the ecosystem you inherit — and how much of your custom code stays portable.

2 · where preprocessing went

Every symbol from the archived module has a home — usually a layer, so the transformation lives inside the model and is exported with it.

3 · the PyTorch interop

On the torch backend the inheritance is real: keras.layers.Layer subclasses torch.nn.Module. That single fact makes the interop work in both directions with no adapter.

4 · which file do you want

Three calls, three artifacts, three purposes. Choosing the wrong one is the most common Keras 3 stumble, because save() stopped producing a SavedModel.
