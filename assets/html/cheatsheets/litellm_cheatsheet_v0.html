LiteLLM cheat sheet

LiteLLM gives you a single, OpenAI-shaped interface to call 100+ providers — OpenAI, Anthropic, Gemini, Bedrock, Azure, Groq, Ollama and more — by just changing the model string. Same request format, same response object (response.choices[0].message.content), everywhere. Use it as a Python SDK (completion()), a Router for load-balancing/fallbacks across deployments, or a standalone proxy gateway. This sheet targets LiteLLM 1.x.

Call Any Model

One function, OpenAI-shaped, for every provider.

1Install & completion()the one call
  • pip install litellm★
    SDK only. Add litellm[proxy] for the gateway server.
  • from litellm import completion r = completion(model="openai/gpt-4o", messages=msgs)★
    The universal call. Swap the model string to change provider — everything else stays identical.
  • r.choices[0].message.content★
    Response follows the OpenAI schema for every provider: choices, message, usage, id, model.
  • export OPENAI_API_KEY=...   ANTHROPIC_API_KEY=...   GEMINI_API_KEY=...
    Keys come from env vars by default (per provider), or pass api_key= explicitly.
2Messages, params, responsethe request
  • msgs = [{"role":"system","content":"..."}, {"role":"user","content":"Hi"}]★
    Standard chat-message list. Multimodal content parts (image/audio) supported for capable models.
  • completion(model, messages, temperature=0.7, max_tokens=500)★
    OpenAI-style params (top_p, stop, n, seed) are translated to each provider's native format.
  • completion(..., response_format={"type":"json_object"})
    JSON mode / structured output; pass a Pydantic model as response_format= where supported.
  • completion(..., tools=tools, tool_choice="auto")
    Function/tool calling with the OpenAI schema; read r.choices[0].message.tool_calls.
3Streaming & asyncnon-blocking
  • for chunk in completion(model, messages, stream=True): print(chunk.choices[0].delta.content or "", end="")★
    Streaming yields OpenAI-style delta chunks for every provider.
  • from litellm import acompletion r = await acompletion(model, messages)★
    Async twin of completion. stream=True gives an async iterator.
  • from litellm import stream_chunk_builder full = stream_chunk_builder(chunks, messages=msgs)
    Reassemble streamed chunks into a single completion object (with usage).
4Embeddings & moreother endpoints
  • from litellm import embedding embedding(model="openai/text-embedding-3-small", input=["txt"])★
    Same unified shape for embeddings. aembedding for async.
  • litellm.transcription(...) · image_generation(...) · rerank(...)
    Audio, image and rerank endpoints where the provider supports them.
  • litellm.completion(model="...", mock_response="hi")
    Return a canned response — test your app without hitting (or paying) a provider.

Providers & Params

The model prefix routes the call; keys and quirks per provider.

5Provider prefixesprovider/model
  • "openai/gpt-4o" · "anthropic/claude-sonnet-4-5"★
    The provider/ prefix picks the backend. OpenAI models can be used prefixless too.
  • "gemini/gemini-2.5-pro" · "groq/llama-3.3-70b" · "mistral/..."
    Hosted providers — each reads its own *_API_KEY env var.
  • "bedrock/anthropic.claude-..." · "azure/<deployment>" · "vertex_ai/..."
    Cloud gateways use their own auth (AWS creds, AZURE_API_BASE+key, GCP project).
  • "ollama/llama3" · "openai/..." + api_base="http://localhost:8000/v1"★
    Local models via Ollama, or any OpenAI-compatible server by setting api_base.
6Keys & provider paramsconfig
  • completion(model, messages, api_key="...", api_base="...")
    Override per call instead of env vars. litellm.api_key = ... to set globally.
  • litellm.drop_params = True★
    Silently drop params a provider doesn't support (instead of erroring) — key for portable code across providers.
  • litellm.get_supported_openai_params(model="...")
    Ask what a given model actually supports before sending.
  • completion(..., num_retries=3, timeout=30)
    Per-call retries & timeout even without the Router.

Router & Reliability

Load-balance across deployments and fail over automatically.

7Router — load balancingmany deployments
  • from litellm import Router router = Router(model_list=[...])★
    A drop-in that spreads calls across multiple deployments of the same logical model — with retries, cooldowns, fallbacks & cost tracking built in.
  • model_list=[{"model_name":"gpt", "litellm_params":{"model":"azure/dep1", "api_key":...}}, ...]★
    Group several real deployments under one model_name; callers just ask for "gpt".
  • router.completion(model="gpt", messages=msgs)★
    Same signature as completion (and router.acompletion). The router picks a healthy deployment.
  • Router(..., routing_strategy="latency-based-routing")
    Also simple-shuffle, least-busy, usage-based-routing (respects per-deployment TPM/RPM limits).
8Fallbacks & retriesfailover
  • Router(..., fallbacks=[{"gpt": ["claude"]}])★
    On a 429/500 for gpt, automatically retry the request on claude. General-error failover.
  • context_window_fallbacks=[...] # needs enable_pre_call_checks=True
    Route to a bigger-context model when the input overflows the current one.
  • content_policy_fallbacks=[...]
    On a content-policy refusal, send to a different provider instead of failing.
  • Router(..., num_retries=3, cooldown_time=60, allowed_fails=2)
    Retries with backoff; a deployment that fails too often is put in cooldown and skipped.

Cost, Observability & Proxy

Track spend, add logging, and expose a gateway for other apps.

9Cost, caching, callbacksobservability
  • from litellm import completion_cost completion_cost(completion_response=r)★
    Dollar cost of a call from token usage + model pricing. Also on r._hidden_params["response_cost"].
  • litellm.success_callback = ["langfuse"] · failure_callback = [...]★
    One-line integrations: Langfuse, Helicone, MLflow, Prometheus, OpenTelemetry, Datadog, S3.
  • litellm.cache = Cache(type="redis") # or "local"
    Response caching to cut cost/latency on repeated prompts.
  • r.usage.prompt_tokens · r.usage.completion_tokens · r.usage.total_tokens
    Token accounting on every response; litellm.token_counter(...) to count before sending.
10Proxy gatewayOpenAI-compatible server
  • litellm --config config.yaml★
    Runs an OpenAI-compatible HTTP gateway in front of all your models — point any OpenAI SDK/app at it.
  • client = OpenAI(base_url="http://localhost:4000", api_key="sk-...")★
    Non-Python apps (or the OpenAI SDK) call the proxy as if it were OpenAI; it routes to any provider.
  • # config.yaml: model_list + router_settings + litellm_settings
    Central place for keys, virtual API keys, budgets/rate-limits per team, fallbacks and logging.
  • virtual keys · per-key budgets · spend tracking
    Issue scoped keys with spend limits — the proxy becomes an org-wide LLM gateway with a dashboard.

Gotchas

The cross-provider surprises.

!Common gotchasread before shipping
  • unsupported params error by default
    Sending e.g. logprobs to a provider that lacks it raises. Set litellm.drop_params=True for portable code.
  • right key for the right prefix
    Each provider reads its own env var (ANTHROPIC_API_KEY, GEMINI_API_KEY, ...). Wrong-key errors usually mean a missing/mismatched var.
  • Azure/Bedrock need extra config
    Azure wants api_base+api_version and the deployment name; Bedrock/Vertex use cloud credentials, not a simple key.
  • costs depend on the price map
    completion_cost relies on LiteLLM's model-price table — a brand-new model may be missing until you update or supply pricing.
  • capabilities still differ
    A unified API doesn't unify features — tool calling, JSON mode, vision and context limits vary by model. Check per-model support.
