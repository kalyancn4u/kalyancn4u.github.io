sentence-transformers cheat sheet

Sentence Transformers (SBERT) computes dense, sparse and reranking embeddings for text (and, in v5, images/audio/video) — the backbone of semantic search, retrieval, RAG and clustering. Three model families: SentenceTransformer (bi-encoder, dense vectors), CrossEncoder (reranker, scores a pair), and SparseEncoder (learned sparse/lexical vectors, new in v5). Each has a matching Trainer. This sheet targets v5.x.

Embed

Load a bi-encoder and turn text into vectors.

1Install & load a modelv5.x
  • pip install "sentence-transformers"★
    Pulls in Transformers + PyTorch. Add [train] extras for the training stack.
  • from sentence_transformers import SentenceTransformer model = SentenceTransformer("all-MiniLM-L6-v2")★
    Small, fast, 384-dim — the classic default. Bigger/better: all-mpnet-base-v2, BAAI/bge-*, Qwen/Qwen3-Embedding-*.
  • SentenceTransformer(id, device="cuda", model_kwargs={"dtype":"auto"})
    Choose device/precision; truncate_dim= for Matryoshka models, backend="onnx"/"openvino" for fast CPU inference.
  • model.get_sentence_embedding_dimension() · model.max_seq_length
    Inspect vector size and the token limit (inputs longer than this are truncated).
2encode() & similarity()text → vectors
  • emb = model.encode(["a sentence", "another"])★
    Returns an (n, dim) numpy array (or a torch tensor with convert_to_tensor=True). Batched & parallelized internally.
  • model.encode(texts, normalize_embeddings=True, batch_size=64, show_progress_bar=True)★
    Normalize to unit length so cosine == dot product. Tune batch_size for throughput.
  • scores = model.similarity(emb1, emb2) # (n1, n2) matrix★
    Uses the model's configured metric (cosine by default). similarity_pairwise for row-aligned pairs.
  • model.similarity_fn_name # "cosine" | "dot" | "euclidean" | "manhattan"
    Set at load via similarity_fn_name=; controls both similarity() and search defaults.
3encode_query / encode_documentasymmetric search
  • corpus_emb = model.encode_document(corpus)★
    Encode the corpus once, keep the tensor as your index. Applies the model's document prompt if it has one.
  • q_emb = model.encode_query("my question")★
    Encode each incoming query with the query prompt. Query/document methods (v5) replace manually prepending prompts.
  • model.similarity(q_emb, corpus_emb)
    Then rank the corpus for the query — the core of a retrieval pipeline.
  • match query & doc encodersgotcha
    Use the same model for both sides. Many retrieval models are asymmetric — skipping query/document prompts silently hurts recall.

Search & Retrieval

Rank a corpus against queries, and shrink/speed up the index.

4Semantic search & utiltop-k
  • from sentence_transformers import util hits = util.semantic_search(q_emb, corpus_emb, top_k=5)★
    Cosine top-k in one call; returns a list (per query) of {"corpus_id", "score"}. Good up to ~1M docs in memory.
  • util.cos_sim(a, b) · util.dot_score(a, b)
    Raw score matrices when you need custom filtering/thresholds before the top-k sort.
  • util.paraphrase_mining(model, sentences)
    Find the most similar pairs within one big list — dedup / near-duplicate detection.
  • scale → a real vector DBnote
    Beyond ~1M vectors, push embeddings into FAISS / pgvector / Qdrant / Milvus for ANN search instead of brute force.
5Prompts & quantized embeddingssmaller / faster
  • model.encode(text, prompt_name="query")
    Apply a named prompt from the model's config, or prompt="query: " to prepend a raw string (many E5/BGE models require this).
  • from sentence_transformers.quantization import quantize_embeddings q = quantize_embeddings(emb, precision="int8")★
    Shrink vectors to int8 (4×) or binary (32×) for cheaper storage/search with small accuracy loss.
  • SentenceTransformer(id, truncate_dim=256)
    Matryoshka models let you truncate the vector to fewer dims for speed — only if the model was trained for it.

Rerank & Sparse

Two more model types: cross-encoders for precise reranking, sparse encoders for lexical retrieval.

6CrossEncoder — rerankingprecise, slower
  • from sentence_transformers import CrossEncoder ce = CrossEncoder("cross-encoder/ms-marco-MiniLM-L6-v2")★
    Scores a (query, doc) pair jointly — far more accurate than bi-encoder cosine, but can't pre-index.
  • ce.predict([("query", "passage A"), ("query", "passage B")])
    Returns a relevance score per pair.
  • ce.rank("query", list_of_docs, top_k=5)★
    The retrieve-then-rerank pattern: bi-encoder fetches ~100 candidates, CrossEncoder reorders the top few.
  • CrossEncoder(id) # v5: multimodal + generative rerankers (LogitScore)
    v5 modularized CrossEncoder for text/image/audio/video and generative reranking.
7SparseEncodernew in v5
  • from sentence_transformers import SparseEncoder se = SparseEncoder("naver/splade-v3")★
    Learned sparse (lexical) vectors — interpretable, keyword-aware, great for hybrid search alongside dense retrieval.
  • emb = se.encode_document(corpus) # sparse tensors
    Same encode/query/document API as the dense model, but outputs sparse vectors.
  • se.similarity(q, d) · util.semantic_search(...)
    Combine dense + sparse scores for hybrid retrieval; trained via SparseEncoderTrainer.

Train / Fine-tune

All three families share a Transformers-style Trainer. Fine-tuning on in-domain pairs is the biggest quality lever.

8SentenceTransformerTrainerthe loop
  • from sentence_transformers import (SentenceTransformerTrainer, SentenceTransformerTrainingArguments)★
    Mirrors the 🌐 Transformers Trainer API (v4+ refactor). CrossEncoder/SparseEncoder have their own Trainer classes.
  • trainer = SentenceTransformerTrainer(model=model, args=args, train_dataset=ds, loss=loss) trainer.train()★
    Provide a dataset, a loss, and args (batch size, epochs, lr). Multi-GPU via accelerate.
  • args = SentenceTransformerTrainingArguments(output_dir="out", num_train_epochs=1, per_device_train_batch_size=64, batch_sampler="no_duplicates")
    no_duplicates sampler matters for in-batch-negative losses. eval_strategy, warmup, fp16/bf16 as usual.
  • model.save_pretrained("out/") · model.push_to_hub("me/model")
    Save + share the fine-tuned embedder.
9Losses & data formatmatch them up
  • from sentence_transformers.losses import MultipleNegativesRankingLoss loss = MultipleNegativesRankingLoss(model)★
    The workhorse for retrieval: needs (anchor, positive) pairs (or triplets); other rows in the batch are the negatives.
  • CoSENTLoss · ContrastiveLoss · TripletLoss · SoftmaxLoss
    Pick by data: labeled similarity scores → CoSENT; (a,pos,neg) triplets → Triplet; NLI-style → Softmax.
  • Dataset columns == loss inputs★
    A 🌐 datasets Dataset whose column order matches the loss (e.g. anchor, positive); a label/score column when the loss needs one.
  • wrong loss for your datagotcha
    The #1 fine-tuning mistake: mismatched loss & dataset shape. Check the loss's docstring for the exact expected columns.

Gotchas

The traps that quietly wreck retrieval quality.

!Common gotchasread before shipping
  • normalize before cosine/dot
    If you compare with dot product, set normalize_embeddings=True — otherwise magnitude skews scores. Cosine is scale-invariant either way.
  • max_seq_length truncation
    Long documents are silently cut at the token limit. Chunk long text before encoding for retrieval.
  • forgetting E5/BGE prompts
    Models like E5/BGE expect "query: " / "passage: " prefixes — use encode_query/encode_document or accuracy tanks.
  • bi-encoder recall vs cross-encoder precision
    Don't rerank everything with a CrossEncoder (too slow). Retrieve with the bi-encoder, rerank only the top candidates.
