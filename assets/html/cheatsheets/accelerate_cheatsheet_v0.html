accelerate cheat sheet

Accelerate lets one PyTorch training script run unchanged on CPU, a single GPU, multi-GPU, multi-node, or TPU — with mixed precision (incl. fp8), FSDP and DeepSpeed a config away. You add ~4 lines (Accelerator(), prepare(), accelerator.backward(), drop manual .to(device)) and launch with accelerate launch. It's the distributed engine under 🌐 Transformers' Trainer, usable standalone. This sheet targets Accelerate 1.x.

The Code Changes

Four edits turn a single-GPU loop into a device-agnostic one.

1Install & Accelerator1.x
  • pip install accelerate★
    Then run accelerate config once to record your machine's setup (interactive).
  • from accelerate import Accelerator accelerator = Accelerator()★
    Create it at the top. It figures out the distributed environment automatically.
  • device = accelerator.device★
    Use this for any tensors you create manually — never hardcode "cuda".
2The training-loop editsprepare + backward
  • model, opt, train_dl, sched = accelerator.prepare(model, opt, train_dl, sched)★
    Edit 1. Wraps everything for the target setup (DDP model, sharded dataloader, etc.). Prepare the dataloader so batches auto-distribute.
  • # remove every .to(device) — prepare handles placement★
    Edit 2. Delete manual device moves for the model, batches & optimizer.
  • outputs = model(batch) loss = loss_fn(outputs, targets) accelerator.backward(loss)★
    Edit 3. Replace loss.backward() — this handles scaling (mixed precision) & accumulation correctly.
  • opt.step(); sched.step(); opt.zero_grad()
    Edit 4 (implicit): the rest of the loop is unchanged. That's the whole port.

Run It

Launch across processes — from CLI or a notebook.

3config & launchCLI
  • accelerate config★
    Interactive Q&A (num GPUs, mixed precision, FSDP/DeepSpeed) → writes default_config.yaml. accelerate config --help for non-interactive.
  • accelerate launch train.py --args★
    The launcher — spawns the right number of processes. Replaces python train.py / torchrun.
  • accelerate launch --num_processes 4 --mixed_precision bf16 train.py
    Override config on the command line for a one-off run.
  • accelerate test · accelerate estimate-memory <model>
    Verify your setup works; estimate a model's memory footprint before launching.
4notebook_launcherJupyter / Colab
  • from accelerate import notebook_launcher notebook_launcher(training_fn, args=(...), num_processes=2)★
    Run multi-GPU from inside a notebook (Colab TPUs/Kaggle) where you can't call accelerate launch.
  • no CUDA init before the launchergotcha
    Don't touch CUDA (create tensors/models on GPU) in the notebook before notebook_launcher — it must fork clean processes. Put all model/loop code inside training_fn.

Precision & Accumulation

Speed and effective batch size, without manual scaler code.

5Mixed precisionfp16 / bf16 / fp8
  • accelerator = Accelerator(mixed_precision="bf16")★
    Set once (or via config/CLI). accelerator.backward then handles loss scaling automatically — no manual GradScaler.
  • with accelerator.autocast(): outputs = model(batch)
    Explicit autocast region if you need it around specific ops.
  • mixed_precision="fp8" # TransformerEngine / MS-AMP backends
    fp8 training on supported hardware for further speedup.
6Gradient accumulation & clippingbigger effective batch
  • accelerator = Accelerator(gradient_accumulation_steps=4)★
    Declare the steps once.
  • with accelerator.accumulate(model): accelerator.backward(loss); opt.step(); opt.zero_grad()★
    Wrap the step in accumulate — it skips the optimizer step & sync on non-boundary iterations for you.
  • accelerator.clip_grad_norm_(model.parameters(), 1.0)★
    Use the accelerator's clip (not torch's) so it works correctly under FSDP/DeepSpeed & mixed precision.
  • accelerator.sync_gradients # True on accumulation boundaries
    Gate logging/clipping to real update steps.

Multi-process Control

Do things once, or gather results from every rank.

7Process control & loggingonce vs everywhere
  • accelerator.print("epoch done")★
    Print from the main process only — avoids N duplicate lines across GPUs.
  • if accelerator.is_main_process: save_something()★
    Guard one-time work (checkpoints, logging to W&B). is_local_main_process for per-node.
  • accelerator.wait_for_everyone()★
    Barrier — sync all processes before/after a critical section (e.g. before loading a just-saved checkpoint).
  • with accelerator.main_process_first(): dataset = load_and_cache()
    Let rank 0 do the download/cache first, then the others reuse it.
8Save / load / gathercheckpoints & metrics
  • all_preds = accelerator.gather_for_metrics(preds)★
    Collect predictions from every process for evaluation — and it drops the duplicated tail samples the distributed sampler adds.
  • model = accelerator.unwrap_model(model) accelerator.save(model.state_dict(), "model.pt")★
    Unwrap the DDP/FSDP wrapper before saving weights, and use accelerator.save (main-process-safe).
  • accelerator.save_state("ckpt/") · accelerator.load_state("ckpt/")★
    Full training state (model, optimizer, scheduler, RNG, step) for exact resume. save_model for just the model.
  • accelerator.gather(t) · accelerator.reduce(t, "mean")
    Low-level collectives when you need them.

Scale & Big Models

Shard huge models for training and inference.

9FSDP / DeepSpeedconfig, not code
  • accelerate config # choose FSDP or DeepSpeed here★
    Enable sharding via config — your training script usually doesn't change. Shards params/grads/optimizer state across GPUs.
  • Accelerator(fsdp_plugin=FullyShardedDataParallelPlugin(...))
    Or configure in code with the plugin (sharding strategy, wrap policy, offload).
  • DeepSpeedPlugin(zero_stage=3, offload_optimizer_device="cpu")
    ZeRO-3 + CPU offload to fit models that don't fit in GPU memory.
10Big-model inferenceload huge weights
  • from accelerate import init_empty_weights with init_empty_weights(): model = MyModel(config)★
    Build the model on the "meta" device with no memory for weights — then load onto real devices.
  • from accelerate import load_checkpoint_and_dispatch model = load_checkpoint_and_dispatch(model, ckpt, device_map="auto")★
    Stream weights and shard across GPU/CPU/disk — this is what powers Transformers' device_map="auto".
  • infer_auto_device_map(model, max_memory={0:"20GiB", "cpu":"64GiB"})
    Compute a custom placement map when the automatic one isn't what you want.
!Common gotchasread before shipping
  • prepare the dataloader too
    If you don't pass the dataloader through prepare(), batches aren't distributed — every GPU sees the same data.
  • unwrap before saving
    Saving a prepared (DDP/FSDP-wrapped) model bakes in the wrapper. accelerator.unwrap_model() first.
  • launch, don't python
    Running python train.py gives one process. Use accelerate launch (or notebook_launcher) to actually go distributed.
  • gather_for_metrics for eval, not gather
    Plain gather keeps the sampler's duplicate padding rows — use gather_for_metrics so your metrics aren't skewed.
