Quick Reference · the fast Python package & project manager

uv cheat sheet0.12.x

One Rust binary that replaces pip, pipx, pyenv, poetry, virtualenv & pip-tools. For a project, three files stay in lockstep: pyproject.toml declares what you want, uv.lock pins the exact resolved versions, and .venv holds what's installed. Every command — add, run, sync — keeps all three honest for you.

The project loop — three files uv keeps in sync for you
Two ways in — a project, or a single script
a project · the poetry / pipenv replacement
uv init myapp && cd myapp   # scaffold
uv add httpx "pytest" --dev   # deps + dev group
uv run python main.py       # auto-syncs, runs
uv run pytest               # in the locked env
uv lock --upgrade            # bump the lockfile
uv sync                     # reproduce it exactly
# commit pyproject.toml + uv.lock
a standalone script · PEP 723 inline deps
uv init --script fetch.py         # add header
uv add --script fetch.py rich       # pin dep
# fetch.py now starts with:
# /// script
# requires-python = ">=3.12"
# dependencies = ["rich>=13"]
# ///
uv run fetch.py     # ephemeral env, just works
uvx ruff check .    # a tool, no install needed
PART I

Projects

pyproject.toml + uv.lock + .venv
01Install uvone binary
  • curl -LsSf https://astral.sh/uv/install.sh | sh★
    Standalone installer, macOS/Linux. No Python or Rust needed.
  • powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
    Windows equivalent.
  • pip install uv · brew install uv
    Also on PyPI, Homebrew, Scoop, WinGet, Docker, and as a GitHub Action.
  • uv self update★
    Upgrade uv in place (standalone installs only).
  • uv --version · uv help
    Version + full CLI reference in the terminal.
02Start a Projectuv init
  • uv init myapp★
    Scaffold: pyproject.toml, main.py, README.md, .python-version, git.
  • uv init
    Initialize in the current directory.
  • uv init --lib mylib★
    A packaged library (src layout + build backend) instead of an app.
  • uv init --app · --package
    App (default) vs a packaged app you can publish.
  • uv init --bare
    Just a pyproject.toml — no sample files, no README, no VCS.
  • uv init --python 3.13
    Pin the project's Python at creation.
03Add & Remove Depsuv add / remove
  • uv add httpx★
    Resolve, update pyproject.toml + uv.lock, install into .venv — all at once.
  • uv add "httpx>=0.27,<1"
    Any PEP 508 spec: version ranges, extras, markers.
  • uv add --dev pytest ruff★
    Into the dev group under [dependency-groups] — not shipped to users.
  • uv add --group docs sphinx
    A named dependency group (PEP 735). --optional NAME for an extra instead.
  • uv add --editable ../mylib
    A local path dep, editable. Also --git URL, --branch, --tag.
  • uv add --bounds major httpx
    Control the written constraint style: >=0.28,<1.0 style bounds.
  • uv remove httpx★
    Drop it from all three files. --dev/--group to target a group.
04Run Commandsuv run
  • uv run python main.py★
    Verifies lock + venv are current, then runs. No activate needed.
  • uv run pytest · uv run ruff check★
    Any entry point installed in the env.
  • uv run -- flask run -p 3000
    Use -- so flags reach your command, not uv.
  • uv run --with rich script.py★
    Add a one-off dependency for this run only — not written to the project.
  • uv run --no-sync python
    Skip the auto-sync check — faster when you know the env is fresh.
  • uv run --env-file .env python app.py
    Load env vars from a file before running.
05Lock & Syncreproduce exactly
  • uv lock★
    Resolve the whole project into uv.lock without installing.
  • uv lock --upgrade★
    Re-resolve to newest allowed versions. --upgrade-package httpx for just one.
  • uv sync★
    Make .venv exactly match uv.lock — installs missing, removes extra.
  • uv sync --frozen★
    Install from the lock as-is; error if it's stale. The CI/production install.
  • uv sync --locked
    Assert the lock is already up to date, then sync — fails if pyproject drifted.
  • uv sync --all-extras --all-groups
    Pull in every optional extra and group. --no-dev to exclude dev.
  • uv lock --check
    CI guard: exit non-zero if the lockfile is out of date.
06Inspect & Exporttree / export
  • uv tree★
    The project's dependency tree. --depth 1, --package httpx to focus.
  • uv tree --invert
    Who depends on this? — trace a transitive dep back up.
  • uv export --format requirements-txt -o requirements.txt★
    Emit a classic pinned requirements.txt from the lock (with hashes).
  • uv export --no-hashes --no-dev
    Trim for a slim runtime requirements file.
  • uv version · uv version --bump minor
    Read or bump the project's own version (patch/minor/major).
07The Files uv Manageswhat's on disk
  • pyproject.toml★
    Your declared requirements & config. Commit it. Hand-edit or use uv add.
  • uv.lock★
    Exact, cross-platform, hashed resolution. Commit it. Never hand-edit.
  • .venv/★
    The real environment. Git-ignore it — it's rebuilt from the lock.
  • .python-version
    The project's default Python. Written by uv python pin.
  • [tool.uv] in pyproject.toml
    uv-specific config: [tool.uv.sources], index URLs, resolution knobs.
PART II

Scripts, Tools & Python

the pipx + pyenv replacement
08Standalone ScriptsPEP 723
  • uv run script.py★
    Run a script in an ephemeral env. Reads inline metadata if present.
  • uv init --script app.py
    Add the PEP 723 metadata header to a new or existing script.
  • uv add --script app.py rich "httpx>=0.27"★
    Pin deps inside the script — the file becomes self-contained & shareable.
  • uv run --with pandas -- script.py
    Ad-hoc deps for a script that has no header.
  • uv run --python 3.11 script.py
    Run under a specific Python — uv fetches it if missing.
  • # /// script ... # dependencies = [...] # ///
    The inline block uv reads. No project, no venv to manage — just the file.
09Tools & uvxthe pipx replacement
  • uvx ruff check .★
    uvx = uv tool run. Runs a CLI in a cached, ephemeral env — nothing installed.
  • uvx --from httpie http GET example.com
    When the command name differs from the package name.
  • uvx ruff@0.6.0 check
    Pin a specific version for this run.
  • uv tool install ruff★
    Install a CLI user-wide onto your PATH — persists across shells.
  • uv tool list · upgrade --all · uninstall ruff
    Manage installed tools. uv tool upgrade --all bumps everything.
  • uv tool update-shell
    Put the tool bin dir on your PATH if it isn't already.
10Python Versionsthe pyenv replacement
  • uv python install 3.12 3.13★
    Download & install standalone CPython builds — no system Python touched.
  • uv python list★
    Every version available/installed. --only-installed to filter.
  • uv python pin 3.13★
    Write .python-version so this project uses 3.13.
  • uv python install 3.13t
    Free-threaded (no-GIL) builds via the t suffix.
  • uv python find · upgrade · uninstall
    Locate, patch-upgrade, or remove a managed Python.
  • uv run --python 3.11 ...
    Almost any command takes --python; uv fetches on demand.
11Cache, Auth & Selfuv's own state
  • uv cache clean · prune★
    Wipe the global cache, or just prune dangling/outdated entries.
  • uv cache dir · size
    Where the cache lives & how big it is. Dedup means it's shared across projects.
  • uv auth login · token · logout
    Store & read credentials for private indexes.newer
  • uv self update
    Upgrade the uv binary itself.
  • uv python dir · uv tool dir
    Where managed Pythons & installed tools live.
PART III

pip Interface, Build & Config

low-level control + publishing
12Virtual Environmentsuv venv
  • uv venv★
    Create .venv in milliseconds. replaces python -m venv.venv
  • uv venv --python 3.12
    Pick the interpreter; uv downloads it if needed.
  • uv venv myenv
    Name it something other than .venv.
  • source .venv/bin/activate
    Optional — with uv run/uv pip you rarely need to activate at all.
  • uv venv --seed
    Seed with pip/setuptools for tools that expect them present.
13The pip Interfaceuv pip
  • uv pip install httpx★
    Drop-in, 10–100× faster pip. Installs into the active/.venv env.pip
  • uv pip install -r requirements.txt★
    Same flags you know. -e . for editable installs too.
  • uv pip sync requirements.txt
    Make the env exactly match the file — removes anything extra.
  • uv pip list · freeze · show httpx
    Inspect installed packages. uv pip tree for the graph.
  • uv pip check
    Verify installed packages have compatible dependencies.
  • uv pip is NOT the project API
    It manages a raw env — it won't touch pyproject.toml or uv.lock. Use uv add for projects.
14Compile Requirementsthe pip-tools replacement
  • uv pip compile requirements.in -o requirements.txt★
    Pin loose requirements into a fully-resolved file.pip-tools
  • uv pip compile --universal ...★
    One platform-independent output that resolves for all OSes.
  • uv pip compile --upgrade
    Re-pin to the newest allowed versions.
  • uv pip compile pyproject.toml
    Compile straight from project metadata.
  • uv pip compile --generate-hashes
    Include hashes for a verifiable install.
15Build & Publishthe twine replacement
  • uv build★
    Build sdist + wheel into dist/. --wheel or --sdist for just one.
  • uv publish★
    Upload dist/* to PyPI. --index / --publish-url for others.twine
  • uv publish --token $PYPI_TOKEN
    Or use trusted publishing in CI — no token in the repo.
  • [build-system] → uv_build
    uv ships its own fast build backend; or use hatchling, setuptools, etc.
  • uv build --all-packages
    Build every member of a workspace.
16WorkspacesCargo-style monorepos
  • [tool.uv.workspace] members = ["packages/*"]★
    Multiple packages, one shared uv.lock — consistent versions across all.
  • uv sync
    From the root, syncs the whole workspace at once.
  • uv run --package api uvicorn app:app
    Target one member by name.
  • uv add --package api httpx
    Add a dep to a specific member.
  • [tool.uv.sources] mylib = {workspace = true}
    Members depend on each other by name, resolved locally.
17Sources & Indexeswhere deps come from
  • [tool.uv.sources] mylib = {git = "https://..."}★
    Override where a dep resolves from: git, path, url, or a named index.
  • [[tool.uv.index]] url = "https://..."
    Declare extra package indexes; pin a package to one with explicit = true.
  • uv add torch --index pytorch=https://...
    The clean way to install e.g. CUDA-specific PyTorch wheels.
  • UV_INDEX_... --default-index
    Replace PyPI as the default index entirely.
  • uv add --no-sources ...
    Ignore [tool.uv.sources] — resolve as a published package would.
18Config & Env Varstune behaviour
  • UV_PYTHON=3.12 · UV_PROJECT_ENVIRONMENT
    Env vars mirror most flags — handy in CI & Docker.
  • UV_PYTHON_DOWNLOADS=never★
    Forbid auto-downloading Python — use only what's installed.
  • UV_CACHE_DIR · UV_NO_CACHE=1
    Relocate or disable the cache (e.g. ephemeral CI runners).
  • uv.toml or [tool.uv]
    Persistent config: project-level in pyproject.toml, or a standalone uv.toml.
  • --offline · --refresh · --no-cache
    Global flags: work offline, force re-fetch, or bypass the cache.
  • --exclude-newer 2026-01-01
    Reproducible resolutions — ignore anything published after a date.
19Gotchas & Habitswhat bites
  • uv pip install won't update pyproject
    In a project, reach for uv add. uv pip is the low-level escape hatch.
  • commit uv.lock, ignore .venv★
    The lock is your reproducibility; the venv is disposable and rebuilt by sync.
  • don't hand-edit uv.lock
    Change pyproject.toml then uv lock. Manual edits get overwritten.
  • uv ignores an active VIRTUAL_ENV in projects
    It prefers the project .venv. Use --active to target the activated one.
  • CI: use --frozen (or --locked)★
    Install from the lock without re-resolving — fast, deterministic, no surprise upgrades.
  • uv is pre-1.0
    Minor versions (0.11→0.12) can carry breaking changes; pin uv in CI.

Four things worth seeing once

Which command to reach for, why the lockfile matters, how the cache makes installs near-instant, and which classic tool each uv command retires — all drawn from behaviour verified against uv 0.12.6.

uv add vs uv pip install

The single most common confusion. uv add is the project API and touches all three files; uv pip install is a low-level env tool that touches none of them.

pyproject vs lockfile

pyproject says what you'll accept; the lock records what you actually got. That gap is the whole point — loose specs resolve to exact, shared versions.

why installs are near-instant

uv downloads and builds each package once into a global cache, then hard-links it into every project's .venv. The second project pays almost nothing.

one tool, many retired

uv folds a whole toolbox into a single binary. Each classic command maps to a uv equivalent — usually faster and with a shared cache.
