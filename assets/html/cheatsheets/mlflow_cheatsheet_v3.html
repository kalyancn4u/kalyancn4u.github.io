Quick Reference · the ML & GenAI lifecycle platform

mlflow cheat sheet

An experiment holds three kinds of record, and MLflow 3 is the release that made the second one first-class. A Run is one execution — params, metrics, tags, artifacts. A LoggedModel is one model with its own id, metrics and artifacts, no longer buried inside a run's artifact folder. A Trace is one request through an LLM app, broken into spans. The Registry sits on top and promotes a model by moving an alias.

Built against the official docs at mlflow.org/docs/latest — the ML track (tracking, tracking APIs, model, model registry, evaluation) and the LLMs & Agents track (tracing, scorers, judges) — plus the MLflow 3 Migration Guide, the Breaking Changes page, the full CLI reference, and the 3.x release notes. — Verified 2026-08-26 against MLflow 3.15.2.

One experiment end to end · and the three records it holds
A tracked, registered, reloadable model in seventeen lines
import mlflow
from mlflow.models import infer_signature

mlflow.set_tracking_uri("http://127.0.0.1:5000")   # without this it writes to ./mlruns
mlflow.set_experiment("fraud-detection")         # created if it does not exist
mlflow.autolog()                                 # params, metrics and the model, for free

with mlflow.start_run(run_name="rf-baseline") as run:
    model.fit(X_train, y_train)
    mlflow.log_params({"n_estimators": 300, "max_depth": 8})
    mlflow.log_metric("val_auc", auc, step=epoch)      # step is optional, metrics are a series

    info = mlflow.sklearn.log_model(
        model,
        name="model",                              # MLflow 3: name=, NOT artifact_path=
        signature=infer_signature(X_train, model.predict(X_train)),
        input_example=X_train[:5],
        registered_model_name="fraud-rf",           # log and register in one step
    )

loaded = mlflow.pyfunc.load_model(info.model_uri)   # use the returned URI, not get_artifact_uri()
Part I

Setup, runs & logging

point MLflow somewhere, open a run, and record what happened
01Install & the packagesthree of them
  • pip install mlflow
    The full platform, including the server and UI. Python 3.10+ since MLflow 3.
  • pip install mlflow-skinny
    Client only — no server, no UI, far fewer dependencies. The right choice inside a training container.
  • pip install mlflow-tracing
    Tracing SDK alone, for instrumenting an app that only needs to emit traces. Do not co-install with full mlflow.
  • pip install "mlflow[genai]"
    Extras also include databricks, gateway, langchain, mcp, auth, kubernetes, azure, sqlserver.
  • pip install 'mlflow<3'
    Pin to 2.x if you are not ready to migrate. MLflow 3 reads 2.x data; the reverse is not true.
  • mlflow --version · mlflow doctor
    doctor dumps environment and config for bug reports; add --mask-envs before pasting it anywhere.
02The CLImlflow --help
  • mlflow server --port 5000
    Starts the tracking server and UI. Binds to localhost only; use --host 0.0.0.0 to expose it.
  • mlflow server --backend-store-uri sqlite:///mlflow.db
    A database backend. Required for the Model Registry — the file store cannot serve it.
  • mlflow server --artifacts-destination s3://bucket
    Proxies artifact traffic through the server, so clients need no cloud credentials.
  • mlflow demo3.x
    Spins up a server pre-populated with demo data. The fastest way to see what the UI offers.
  • mlflow models serve -m "models:/fraud-rf@champion" -p 1234
    Local REST endpoint at /invocations. Defaults to a virtualenv built from the model's requirements.
  • mlflow run . -P lr=0.02
    Runs an MLproject entry point with parameters.
  • mlflow gc --older-than 30d
    Permanently deletes runs already in the deleted stage. Deletion in the UI only soft-deletes.
  • mlflow db upgrade sqlite:///mlflow.db
    Migrates the schema after an MLflow upgrade. Back up first — migrations are not transactional.
  • mlflow experiments search · mlflow runs list --experiment-id 1
    Browse from the shell. Both need MLFLOW_TRACKING_URI set.
  • mlflow artifacts download -u "runs:/<id>/plots"
    Pull artifacts without writing Python.
03Where it writesURI & the two stores
  • mlflow.set_tracking_uri("http://127.0.0.1:5000")
    Call it before anything else. Without it everything lands in a local ./mlruns folder.
  • mlflow.set_tracking_uri("sqlite:///mlflow.db")
    Talk to a database directly, no server needed. Enough to unlock the registry for solo work.
  • export MLFLOW_TRACKING_URI=...
    The CLI does not read your Python config — most CLI commands need this variable set.
  • mlflow.set_registry_uri("databricks-uc")
    Registry can live somewhere other than tracking — this is how you target Unity Catalog.
  • # backend store = metadata · artifact store = files
    Two separate things. Params and metrics go to one, model weights and plots to the other.
  • mlflow.get_tracking_uri()
    Check what you are actually connected to before blaming the server.
  • # file store cannot serve the Model Registry
    If registry calls fail, this is nearly always why. Move to SQLite or Postgres.
04Experimentsthe container
  • mlflow.set_experiment("fraud-detection")
    Creates it if missing. Everything after this call lands there.
  • mlflow.create_experiment(name, artifact_location="s3://bucket", tags={...})
    Explicit creation when you need a custom artifact root or tags from the start.
  • mlflow.search_experiments(filter_string="tags.team = 'ds'")
    Find experiments programmatically.
  • MLFLOW_EXPERIMENT_NAME · MLFLOW_EXPERIMENT_ID
    Set the target from the environment so the same script works across stages unchanged.
  • mlflow experiments create -n "my-exp"
    Same thing from the shell.
  • # deleting an experiment only marks it deleted
    The file store moves it to .trash. Space is reclaimed only by mlflow gc.
05Start a run★context manager
  • with mlflow.start_run() as run:
    The form to use. Ends the run on exit and marks it FAILED if the block raises.
  • mlflow.start_run(run_name="rf-baseline")
    A readable label. Without one MLflow generates a random name.
  • mlflow.start_run(nested=True)
    Child run under the currently active one — the pattern for sweeps and CV folds.
  • mlflow.start_run(run_id=rid)
    Reopen an existing run to append more data to it.
  • mlflow.end_run(status="FAILED")
    Manual close. Statuses: FINISHED, FAILED, KILLED.
  • run.info.run_id · run.info.status
    Identity and state. Keep the id if you plan to reopen or reference the run.
  • mlflow.active_run() · mlflow.last_active_run()
    The run in progress, and the one that just finished — handy after autologging.
  • run_info.run_uuidremoved in 3
    Use run_info.run_id.
06Params, metrics & tags★the run record
  • mlflow.log_param("lr", 0.01) · mlflow.log_params({...})
    Inputs. Stored as strings, and immutable — re-logging a key with a different value raises.
  • mlflow.log_metric("auc", 0.94) · mlflow.log_metrics({...})
    Outputs. Numeric and append-only — a metric is a series, not a single value.
  • mlflow.log_metric("loss", l, step=epoch)
    The x-axis for charts. Any 64-bit int — may be negative, out of order, or have gaps.
  • mlflow.log_metric(k, v, timestamp=ms)
    Custom wall-clock, in milliseconds. Passing seconds puts your point in 1970.
  • mlflow.log_metric(k, v, model_id=..., dataset=...)3.x
    Attaches the metric to a specific model checkpoint and dataset, not just the run.
  • mlflow.set_tag("env", "prod") · mlflow.set_tags({...})
    Mutable labels you can search on. Unlike params, tags can be changed later.
  • mlflow.set_tag("mlflow.note.content", "...")
    The one system tag you are meant to set. Renders as a Notes panel on the run page.
  • # auto tags: mlflow.source.name / .user / .source.git.commit
    Set for you. Git commit is captured whenever you run inside a repo.
  • # params are strings — log_param("n", 300) reads back "300"
    Cast on the way out, or filter with the numeric form in search.
07Autologone line, most of it
  • mlflow.autolog()
    Enables every installed integration at once. Params, metrics, the model and plots, with no log calls.
  • mlflow.sklearn.autolog() · mlflow.pytorch.autolog()
    Per-library, when the blanket call captures more than you want.
  • mlflow.autolog(log_models=False)
    Track metrics without uploading a model artifact every fit — the usual fix for a bloated store.
  • mlflow.autolog(disable=True)
    Turn it off again for a block.
  • mlflow.autolog(silent=True)
    Suppresses the integration warnings that flood notebook output.
  • mlflow.autolog(exclusive=True)
    Blocks your manual calls from mixing into an autologged run.
  • mlflow.openai.autolog() · mlflow.langchain.autolog()
    For LLM libraries autolog emits traces, not metrics. 40+ integrations. See card 19.
  • # autolog starts a run if none is active
    And ends it when fit returns. Wrap in start_run if you want to add your own metrics after.
  • every_n_iterTF, removed in 3
    Write a callback if you need a custom logging frequency.
08Artifacts & datasetsfiles and inputs
  • mlflow.log_artifact("confusion.png")
    One file. Optional artifact_path= puts it in a subfolder.
  • mlflow.log_artifacts("./plots/")
    A whole directory in one call.
  • mlflow.log_figure(fig, "roc.png")
    A matplotlib or plotly figure straight from memory — no temp file.
  • mlflow.log_table(data, "preds.json") · mlflow.log_text(s, "notes.txt")
    Also log_dict and log_image for the common cases.
  • ds = mlflow.data.from_pandas(df, name="train")
    Also from_numpy, from_spark, from_huggingface. Captures schema and a digest.
  • mlflow.log_input(ds, context="training")
    Records which data produced the run — the missing half of reproducibility.
  • mlflow.artifacts.download_artifacts(run_id=..., artifact_path=...)
    Fetch them back to local disk.
  • mlflow.get_artifact_uri("model")wrong in 3
    Models no longer live under the run's artifacts, so this path will not load. Use the URI returned by log_model.
09Nested runs & parallelismmany runs at once
  • with mlflow.start_run(run_name="sweep") as parent:
    Outer run holds the summary; each trial becomes a child.
  • with mlflow.start_run(nested=True):
    The child. Collapses under the parent in the UI instead of flooding the list.
  • filter_string=f"tags.mlflow.parentRunId = '{rid}'"
    How you fetch the children back out.
  • mlflow.set_tracking_uri(...) # inside each worker
    Required with multiprocessing — a spawned process does not inherit the URI.
  • with ThreadPoolExecutor() as ex: ...
    Threads share the active run, so give each worker a nested=True run of its own.
  • mlflow.set_tag("fold", k)
    Tag each child so the comparison table sorts sensibly.
Part II

Models, flavors & the registry

where MLflow 3 changed most — and where old tutorials break
10Log a model★name=, not artifact_path=
  • info = mlflow.sklearn.log_model(model, name="model")
    The single biggest MLflow 3 change. artifact_path= became name=, and name is what makes the model searchable.
  • info.model_uri · info.model_id
    What log_model hands back. Keep the URI — it is the only reliable way to load the model again.
  • mlflow.pyfunc.log_model(name="m", python_model=obj)
    No open run required in MLflow 3. Models are first-class entities now.
  • log_model(..., registered_model_name="fraud-rf")
    Logs and registers in one step, creating the next version automatically.
  • log_model(..., step=epoch)3.x
    Several checkpoints in one run, each a separate LoggedModel with its own metrics.
  • mlflow.sklearn.save_model(model, path="./out")
    Write to disk without a tracking server at all.
  • mlflow.create_external_model(name="agent")3.x
    Track a model whose weights live elsewhere — a hosted LLM or a deployed agent.
  • log_model(model, "model")MLflow 2 form
    The positional artifact_path that nearly every tutorial online still shows.
  • code_path= · example_no_conversion=removed in 3
    Also requirements_file (PyTorch) and inference_config (Transformers).
11Model URIs★four shapes
  • models:/<model_id>3.x
    One specific logged model. The new default, and what info.model_uri gives you.
  • models:/<name>/<version>
    A registered version, e.g. models:/fraud-rf/3. Immutable — use it for reproducibility.
  • models:/<name>@champion
    Whatever the alias currently points at. Use it in serving so you can promote without a redeploy.
  • /local/path · s3://bucket/path
    A saved model directory, straight off disk or object storage.
  • runs:/<run_id>/<path>deprecated
    Still resolves, but slated for removal. The MLflow 2 form every old snippet uses.
  • models:/<name>/Productionstage URI
    Stage-based URIs went with stages. Community cheat sheets are full of these.
  • ResourceNotFound on load_model
    Almost always a stale URI shape. Artifacts moved to experiments/<id>/models/<model_id>/ in MLflow 3.
12Signatures & examplesthe contract
  • from mlflow.models import infer_signature
    The helper you want in essentially every training script.
  • sig = infer_signature(X_train, model.predict(X_train))
    Derives input and output schema from real data. Pass it to log_model(signature=sig).
  • log_model(..., input_example=X[:5])
    Infers the signature for you and validates that the model can actually predict before logging.
  • mlflow.models.set_signature(model_uri, sig)
    Attach a signature after the fact — needed for Unity Catalog, which requires one.
  • mlflow.models.validate_serving_input(model_uri, payload)
    Checks a JSON payload against the signature before you deploy anything.
  • mlflow.models.update_model_requirements(uri, "add", ["scikit-learn"])
    Fix a missing dependency without retraining and re-logging.
  • info.signature_dictremoved in 3
    Use info.signature.
  • # no signature = no validation at serving time
    The model will happily accept malformed input and fail deep inside the framework instead.
13Flavorsmlflow.<flavor>
  • mlflow.sklearn · mlflow.xgboost · mlflow.lightgbm
    The classical ML trio. All expose log_model, save_model, load_model, autolog.
  • mlflow.pytorch · mlflow.tensorflow · mlflow.keras
    Deep learning. Each stores the native format plus a pyfunc wrapper.
  • mlflow.transformers · mlflow.sentence_transformers
    HuggingFace pipelines and embedding models, logged whole.
  • mlflow.langchain · mlflow.openai · mlflow.llama_index
    LLM app flavors. These are also the tracing integrations.
  • mlflow.spark · mlflow.onnx · mlflow.catboost · mlflow.prophet
    The rest of the common set — 20+ flavors ship in the box.
  • mlflow.pyfunc
    The universal one. Every flavor also saves a pyfunc wrapper, which is what serving uses.
  • mlflow.fastai · mlflow.mleap · mlflow.diviner · mlflow.gluonremoved in 3
    Wrap in pyfunc instead; for gluon use pytorch or onnx.
14pyfunc & custom modelsanything at all
  • class M(mlflow.pyfunc.PythonModel):
    Subclass this and any Python object becomes a loggable, servable MLflow model.
  • def predict(self, context, model_input, params=None):
    The one method you must implement. context exposes your artifacts at load time.
  • def load_context(self, context):
    Runs once when the model loads — the right place to open weights or a tokenizer.
  • log_model(name="m", python_model=M(), artifacts={"w": path})
    Ships extra files alongside the code; reachable via context.artifacts["w"].
  • log_model(..., pip_requirements=["scikit-learn==1.5.0"])
    Pin the environment explicitly instead of trusting inference.
  • log_model(..., extra_pip_requirements=[...])
    Add to the inferred set rather than replacing it.
  • mlflow.models.ModelConfig()
    Parameterise a model from a YAML config instead of hard-coding it.
15Load & predictgetting it back
  • m = mlflow.pyfunc.load_model(uri)
    Works for every flavor and gives a uniform predict. The safe default.
  • m = mlflow.sklearn.load_model(uri)
    Returns the native object, so you keep predict_proba and the rest of its API.
  • m.predict(df)
    pyfunc takes a DataFrame, numpy array, list or dict, and validates against the signature.
  • mlflow.models.predict(model_uri=..., input_data=...)
    Runs prediction in the model's own environment — catches dependency drift before deployment.
  • mlflow.pyfunc.load_model(f"models:/{info.model_id}")
    Load by model id when you have searched for a checkpoint rather than logged it.
  • mlflow.get_logged_model(model_id) · mlflow.last_logged_model()
    Fetch LoggedModel metadata without materialising the weights.
16The Model Registry★needs a database
  • mlflow.register_model(model_uri, name="fraud-rf")
    Promotes a logged model into the registry, creating version 1, then 2, then 3…
  • log_model(..., registered_model_name="fraud-rf")
    Same result in one step, at training time.
  • client = mlflow.MlflowClient()
    Everything below hangs off this. Importable straight from mlflow.
  • client.create_registered_model("fraud-rf")
    Create the empty collection up front.
  • client.search_model_versions("name='fraud-rf'")
    List versions with their metadata.
  • client.set_model_version_tag(name, "3", "validation", "passed")
    Record gate results on the version itself, where an auditor can find them.
  • client.update_model_version(name, "3", description="...")
    Markdown description per version.
  • client.delete_model_version(name, "3")
    Permanent. There is no undo.
  • # registry requires a database-backed store
    With the default file store the registry simply is not available.
17Aliases, not stagesthe 2.9 migration
  • client.set_registered_model_alias(name, "champion", "3")
    The replacement for stages. Any name you like, pointed at any version.
  • models:/fraud-rf@champion
    Target the alias in serving. Promotion becomes a one-line alias move, with no redeploy.
  • client.get_model_version_by_alias(name, "champion")
    Resolve an alias to the concrete version behind it.
  • client.delete_registered_model_alias(name, "champion")
    Remove it. Re-setting an existing alias just moves it — no need to delete first.
  • # one registered model per environment
    The documented pattern: dev.fraud-rf, staging.fraud-rf, prod.fraud-rf, each with its own aliases.
  • client.set_registered_model_tag(name, "task", "classification")
    Tags carry the status labelling that stages used to imply.
  • client.transition_model_version_stage(...)deprecated 2.9
    Still present for backward compatibility, but the four fixed stages are on the way out.
  • client.get_latest_versions(name, stages=["Production"])deprecated
    Deprecated with the rest of the stage API.
  • # the registry overview page still says "transition between stages"doc bug
    Its own concepts table below lists only aliases and tags. Follow the table, not the prose.
18Serving & deploymentmlflow models
  • mlflow models serve -m "models:/fraud-rf@champion" -p 1234
    Local REST server. POST to /invocations.
  • -d '{"dataframe_split": {"columns": [...], "data": [[...]]}}'
    One of four payload keys: dataframe_split, dataframe_records, instances, inputs.
  • --env-manager local|virtualenv|uv|conda
    Defaults to virtualenv, which rebuilds the model's environment. local is far faster when you already match.
  • mlflow models build-docker -m URI -n my-image
    Container serving the model on port 8080.
  • mlflow models generate-dockerfile -m URI -d ./out
    Emits the Dockerfile instead of building, so you can edit it into your own pipeline.
  • mlflow models predict -m URI -i data.csv -t csv
    Batch scoring from the shell, no server involved.
  • mlflow deployments create -t sagemaker -m URI --name app
    Targets include sagemaker, databricks, openai and http, plus community plugins.
  • mlflow deployments start-serverremoved in 3
    The deployment server is gone. Use mlflow models serve, containers, or mlflow gateway start.
Part III

Tracing, evaluation & operations

the GenAI half of MLflow 3, plus querying, projects and the sharp edges
19Tracing★since 2.14, flagship in 3
  • mlflow.openai.autolog()
    One line and every call is traced. 40+ integrations — langchain, llama_index, anthropic, dspy, crewai, bedrock.
  • @mlflow.trace
    Decorate any function to capture inputs, outputs, latency and exceptions as a span.
  • @mlflow.trace(name="retrieve", span_type="RETRIEVER")
    Named, typed spans render specially in the UI — retriever spans show documents.
  • mlflow.trace(some_external_fn)(args)
    Wrap a third-party function you cannot decorate.
  • mlflow.search_traces(filter_string=..., model_id=...)
    Query traces back as a DataFrame — the basis of an evaluation dataset built from production.
  • mlflow.tracing.disable() · mlflow.tracing.enable()
    Global off switch, for benchmarking or tests.
  • mlflow.set_active_model(name="agent-v2")3.x
    Links every subsequent trace to that model, so you can compare versions in production.
  • trace_destination= · mlflow.tracing.set_destination()3.3
    Route traces to a specific experiment without a global set_experiment.
  • # @mlflow.trace goes OUTERMOST — except under @app.route
    Top of the stack for ordinary decorators; below web-framework route decorators. Wrong order truncates the trace.
  • # same-named spans get _1, _2 suffixes
    Name spans distinctly if you plan to filter on them.
20Spans by handfiner control
  • with mlflow.start_span(name="rerank") as span:
    Trace a block rather than a whole function. Nests inside whatever is already active.
  • span.set_inputs({...}) · span.set_outputs({...})
    Populate the span yourself when the values are not just the arguments.
  • span.set_attributes({"k": 5})
    Arbitrary metadata — token counts, model name, retrieval depth.
  • mlflow.get_current_active_span()
    Reach the active span from deep inside a call stack without threading it through.
  • mlflow.update_current_trace(tags={...})
    Tag the whole trace, e.g. with a session or user id, for later filtering.
  • span_type="LLM"|"RETRIEVER"|"TOOL"|"AGENT"|"CHAIN"
    The recognised types. Getting them right is what makes the trace view readable.
  • mlflow.tracing.set_span_chat_messages(...)
    Render a span as a chat transcript in the UI.
  • mlflow.log_feedback() · mlflow.log_expectation()
    Attach human judgements to a trace — the raw material for judge alignment.
21GenAI evaluation★mlflow.genai
  • mlflow.genai.evaluate(data=ds, predict_fn=f, scorers=[...])
    The MLflow 3 evaluation entry point for LLM apps. Distinct from mlflow.models.evaluate.
  • [{"inputs": {...}, "expectations": {...}}]
    The dataset shape — a plain list of dicts. inputs is passed straight to predict_fn.
  • "expectations": {"expected_facts": [...]}
    What Correctness grades against. Some judges want expected_response instead.
  • mlflow.genai.evaluate(data=mlflow.search_traces(...))
    Evaluate real production traffic by feeding traces in as the dataset.
  • mlflow.genai.datasets.create_dataset(...)
    Persist an evaluation set so runs stay comparable over time.
  • mlflow datasets list --experiment-id 1
    Inspect stored evaluation datasets from the shell.
  • @mlflow.test3.14
    Write GenAI regression tests as plain pytest functions and gate them in CI.
  • mlflow.evaluate(model_type="question-answering")legacy
    The 2.x LLM evaluation path. Superseded by mlflow.genai.evaluate.
22Scorers & LLM judgeshow quality is graded
  • from mlflow.genai.scorers import Correctness, Guidelines
    Built-in judges. Also RelevanceToQuery, Safety, Groundedness, RetrievalSufficiency.
  • Guidelines(name="tone", guidelines="Must stay formal.")
    A judge written in plain English — the cheapest way to encode a house rule.
  • @scorer def is_concise(outputs) -> bool:
    Deterministic code-based scorer. No LLM, no cost, no variance — prefer it where the rule is mechanical.
  • from mlflow.genai.judges import make_judge
    Custom judge with your own instructions and grading scale.
  • make_judge(name=..., instructions="... {{ inputs }} ... {{ outputs }}")
    Instructions must contain at least one of {{ inputs }}, {{ outputs }}, {{ expectations }}, {{ trace }}.
  • Correctness(model="anthropic:/claude-sonnet-4-20250514")
    Any provider in <provider>:/<model> form; others reachable through LiteLLM.
  • MLFLOW_GENAI_JUDGE_DEFAULT_MODEL
    Set the judge model once instead of on every scorer.
  • mlflow scorers list --builtin
    Enumerate what ships in your installed version rather than guessing.
  • # the default judge model is OpenAI gpt-4o-mini
    So a bare Correctness() needs an OpenAI key, and quietly costs money per row.
23Classical evaluationmlflow.models.evaluate
  • mlflow.models.evaluate(model, data, targets="label", model_type="classifier")
    Computes the standard metric set and logs plots automatically.
  • model_type="classifier"|"regressor"
    Decides which metrics and charts you get.
  • evaluators="default" · extra_metrics=[...]
    Add your own metrics on top of the built-in set.
  • mlflow.validate_evaluation_results(r1, r2)
    The MLflow 3 way to compare a candidate against a baseline.
  • MetricThreshold(greater_is_better=True)
    Note the rename — it was higher_is_better in 2.x.
  • evaluator_config={"log_model_explainability": True}
    SHAP explanations are off by default in MLflow 3; add "log_explainer": True to keep the explainer too.
  • baseline_model= · custom_metrics=removed in 3
    Use validate_evaluation_results and extra_metrics respectively.
24Search & querygetting results back
  • df = mlflow.search_runs(experiment_ids=["1"])
    Returns a pandas DataFrame — one row per run, columns for every param and metric.
  • filter_string="metrics.auc > 0.9 AND params.model = 'rf'"
    SQL-like. Prefixes: metrics., params., tags., attributes..
  • order_by=["metrics.auc DESC"], max_results=5
    Leaderboard in one call.
  • mlflow.search_logged_models(filter_string="metrics.acc > 0.95")3.x
    Search models rather than runs — the natural way to pick a checkpoint to deploy.
  • order_by=[{"field_name": "metrics.f1", "ascending": False}]
    Note the shape: search_logged_models takes dicts, while search_runs takes strings.
  • datasets=[{"dataset_name": "test_set"}]
    Compare models only on metrics from the same dataset — otherwise the ranking is meaningless.
  • client.search_runs(exp_id, order_by=["metrics.loss ASC"])[0]
    The client form returns Run objects instead of a DataFrame.
  • mlflow.search_traces() · mlflow.search_experiments()
    Same grammar across the other record types.
  • output_format="list"|"pandas"
    Objects when you need attributes, DataFrame when you want to plot.
25ProjectsMLproject
  • MLproject # a YAML file at the repo root
    Declares the environment, entry points and parameters so a run is reproducible by anyone.
  • python_env: python_env.yaml
    Preferred over conda_env. Also accepts docker_env for full isolation.
  • entry_points: main: {parameters: {lr: {type: float, default: 0.01}}}
    Typed parameters with defaults, validated before the run starts.

    Run a specific entry point locally with overrides.
  • mlflow run git@github.com:org/repo.git -v <commit>
    Run straight from a Git ref — nothing to clone, and the commit is recorded.
  • --env-manager local|virtualenv|uv|conda
    uv is by far the fastest; local skips environment building entirely.
  • mlflow.run(uri, parameters={...})
    Launch a project from Python, e.g. to orchestrate a multi-step pipeline.

26What the tutorials still teach★MLflow 2 habits
  • log_model(model, "model")artifact_path
    The big one. Now log_model(model, name="model"). Every cheat sheet online still shows the old form.
  • load_model(f"runs:/{run_id}/model")deprecated
    Use info.model_uri or models:/<model_id>. Model artifacts no longer sit under the run.
  • mlflow.get_artifact_uri("model")wrong path
    Silently returns a path with no model at it, then fails with ResourceNotFound.
  • models:/name/Productionstages
    Stages deprecated in 2.9. Use models:/name@champion.
  • MLflow Recipesremoved
    Gone in MLflow 3 along with its whole module.
  • mlflow.fastai · mlflow.mleap · mlflow.gluon · mlflow.divinerremoved
    Four flavors dropped. Wrap in pyfunc.
  • baseline_model= · higher_is_better=renamed/removed
    In evaluation: use validate_evaluation_results and greater_is_better.
  • run_info.run_uuid · mlflow.gitBranchNameremoved
    run_id, and the git branch/repo tags no longer exist.
  • mlflow deployments start-serverremoved
    Along with the gateway routes and route_type config keys.
  • MLFLOW_GCS_DEFAULT_TIMEOUTremoved
    Configure timeouts through the GCS client library instead.
27When something goes wrongthe usual suspects
  • # everything logged to ./mlruns, nothing in the UI
    No set_tracking_uri. The client defaults to a local folder and never warns you.
  • # CLI sees no runs but Python does
    The CLI does not read your Python config. Export MLFLOW_TRACKING_URI.
  • # registry API errors out entirely
    You are on the file store. The registry needs a database backend.
  • # ResourceNotFound loading a model you just logged
    Stale URI shape. Use the model_uri that log_model returned.
  • # "Changing param values is not allowed"
    Params are immutable. Log it once, or use a tag if it really needs to change.
  • # metrics look like a flat line
    You logged without step=, so every point landed on step 0.
  • # serving fails on dependencies
    Test with mlflow.models.predict(), which runs in the model's own environment, then patch with update_model_requirements.
  • # traces are empty or truncated
    Decorator order. @mlflow.trace outermost — except under a web framework route decorator.
  • # the store keeps growing
    Deletes are soft. Run mlflow gc --older-than 30d, and consider autolog(log_models=False).
  • # upgraded MLflow, server will not start
    Run mlflow db upgrade <uri>. Back up the database first.
  • mlflow doctor --mask-envs
    Dumps versions, URIs and environment for a bug report, with secrets hidden.

Four things worth seeing

Almost every MLflow 3 error traces back to one of these four pictures being out of date in your head.

Where model artifacts moved

Models left the run's artifact folder and got a directory of their own. This one relocation is why old load paths return ResourceNotFound.

The model URI decoder ring

Six shapes, four of them current. Picking the wrong one is the most common MLflow error, because the deprecated forms still appear in nearly every tutorial.

Stages became aliases

Four fixed stages were too rigid, so MLflow split the idea in two: a registered model per environment, and aliases naming the version that serves traffic inside each.

What a trace looks like

A trace is one request; spans are the nested steps inside it. Autolog produces them for known libraries, @mlflow.trace for everything you wrote yourself.
