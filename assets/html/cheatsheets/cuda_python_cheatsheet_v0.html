CUDA Python cheat sheet

CUDA Python (cuda-python) is NVIDIA's official Python interface to CUDA. It's now a metapackage of independently versioned parts: cuda.bindings — thin, 1:1 Python bindings to the CUDA Driver, Runtime, and NVRTC C APIs; and cuda.core — a higher-level, Pythonic layer (Device, Stream, Program, launch) that hides the boilerplate. Use it to compile and launch your own CUDA C++ kernels, manage device memory, and interop with CuPy/Numba/PyTorch. Targets cuda-python 13.x (CUDA 12/13), Python 3.9+.

Reach for cuda.core for a clean Device/Stream/launch workflow; drop to cuda.bindings when you need an exact C API call. Interop lets you share memory with CuPy/Torch instead of copying.

Setup & Device

Install the metapackage (or just the part you need); select a GPU.

1Install & the splitmetapackage
  • pip install cuda-python★
    The umbrella metapackage — pulls in cuda-bindings + cuda-core. Needs an NVIDIA GPU + driver; the CUDA toolkit libs come via pip wheels.
  • pip install cuda-core cuda-bindings # install parts independently
    Each subpackage is versioned separately now, so you can pin just what you use.
  • from cuda.core.experimental import Device, Program, LaunchConfig, launch from cuda.bindings import driver, runtime, nvrtc★
    Two import roots: high-level cuda.core.experimental, low-level cuda.bindings.*.
  • # old: from cuda import cuda, cudart, nvrtc (pre-12.x layout)migration
    The flat from cuda import cuda layout was replaced by cuda.bindings.driver / .runtime / .nvrtc. Update old code.
2Device & contextcuda.core
  • dev = Device(0) dev.set_current()★
    Device wraps a GPU + its context. set_current() makes it active for this thread.
  • dev.name · dev.compute_capability · dev.properties
    Query the device. Device().device_id; iterate all GPUs with range(Device.num_devices)-style helpers.
  • stream = dev.create_stream()★
    A Stream is the ordered queue you submit compiles, copies, and kernel launches to (card 9).
  • arch = "".join(str(i) for i in dev.compute_capability) # e.g. "90"
    You'll pass the arch (sm_90) to the compiler in card 3.

Run Kernels (cuda.core)

Compile CUDA C++ at runtime, configure the grid, and launch.

3Compile a kernelNVRTC, made easy
  • code = r''' extern "C" __global__ void add(float* a, float* b, float* c, int n){ int i = blockIdx.x*blockDim.x + threadIdx.x; if (i < n) c[i] = a[i] + b[i]; }'''★
    Write the kernel as a CUDA C++ string. Use extern "C" so the name isn't mangled.
  • from cuda.core.experimental import Program, ProgramOptions prog = Program(code, code_type="c++", options=ProgramOptions(arch="sm_90"))★
    Program compiles source via NVRTC. Set target arch through ProgramOptions.
  • mod = prog.compile("cubin") add = mod.get_kernel("add")★
    Compile to a module ("cubin" or "ptx"), then grab the kernel handle by name.
4Launch config & launchgrid × block
  • block = 256 grid = (n + block - 1) // block cfg = LaunchConfig(grid=grid, block=block)★
    LaunchConfig replaces the <<<grid, block>>> syntax. Add shmem_size= for dynamic shared memory.
  • launch(stream, cfg, add, a_ptr, b_ptr, c_ptr, np.int32(n))★
    Submit the kernel to a stream with its arguments (device pointers + scalars). It runs asynchronously.
  • stream.sync()★
    Block until the stream's queued work (launch, copies) finishes before reading results back.
  • # pass scalars with the right dtype (np.int32/float32), not python intgotcha
    Kernel arg types must match the C++ signature exactly — wrap scalars with numpy dtypes.
5Memory & buffersallocate & copy
  • buf = dev.allocate(n * 4) # device Buffer, n float32s★
    Device.allocate() returns a device Buffer. buf.handle is the raw pointer to pass to launch.
  • buf.copy_from(host_array, stream=stream) buf.copy_to(host_out, stream=stream)★
    Async host↔device transfers on a stream. Buffers follow the memory-resource model for pooled allocation.
  • buf.close() # or use as a context manager
    Free device memory explicitly (or scope it with with).

Low-level Bindings

1:1 access to the CUDA C APIs when you need exact control.

6Runtime APIcudart, in Python
  • from cuda.bindings import runtime as cudart err, = cudart.cudaSetDevice(0)★
    The Runtime API mirrors cudart 1:1. Every call returns a tuple whose first element is an error code.
  • err, dptr = cudart.cudaMalloc(n * 4) err, = cudart.cudaMemcpy(dptr, hptr, n*4, cudart.cudaMemcpyKind.cudaMemcpyHostToDevice)★
    Classic malloc/memcpy flow. Enums are nested (cudaMemcpyKind.*). cudaFree, cudaDeviceSynchronize, cudaMemset.
  • err, count = cudart.cudaGetDeviceCount() err, props = cudart.cudaGetDeviceProperties(0)
    Device enumeration & properties, exactly as in C.
7Driver & NVRTCthe low road
  • from cuda.bindings import driver, nvrtc driver.cuInit(0) err, ctx = driver.cuCtxCreate(0, dev)
    The Driver API (cu*): explicit context/module/stream management — the manual version of what cuda.core automates.
  • err, prog = nvrtc.nvrtcCreateProgram(src, b"k.cu", 0, [], []) nvrtc.nvrtcCompileProgram(prog, len(opts), opts)
    NVRTC runtime compilation at the C level. Fetch PTX with nvrtcGetPTX, load via cuModuleLoadData + cuModuleGetFunction.
  • driver.cuLaunchKernel(func, gx,gy,gz, bx,by,bz, shmem, stream, args, 0)
    The raw launch. cuda.core.launch exists precisely so you rarely write this.
  • from cuda.bindings import nvjitlink, nvvm # link/IR tooling
    Bindings also cover nvJitLink, NVVM, nvFatbin, cuFile (GPUDirect Storage), and NVML.
8Error checkingcheck every call
  • def CHECK(res): err, *vals = res if err != cudart.cudaError_t.cudaSuccess: raise RuntimeError(cudart.cudaGetErrorString(err)) return vals[0] if len(vals)==1 else vals★
    Bindings never raise — you must check the returned error code. A tiny helper keeps call sites clean.
  • ptr = CHECK(cudart.cudaMalloc(n*4))
    Wrap every binding call. For the driver API compare against driver.CUresult.CUDA_SUCCESS.
  • # silent wrong results usually = an unchecked error codegotcha
    cuda.core raises Python exceptions on failure; the raw bindings do not — don't skip the check.

Streams & Interop

Overlap work with streams/events; share GPU memory instead of copying.

9Streams & eventsconcurrency
  • s1 = dev.create_stream(); s2 = dev.create_stream() launch(s1, cfg, k1, ...); launch(s2, cfg, k2, ...)★
    Independent streams run concurrently — overlap kernels with copies for throughput.
  • e = dev.create_event(); e.record(s1) s2.wait(e)
    Events synchronize across streams and time GPU work. e.sync() waits; Event.elapsed_time(a,b) measures.
  • stream.sync() · dev.sync()
    Sync a single stream or the whole device. CUDA graphs (capture a stream, replay) are exposed for launch-overhead-bound workloads.
10Array interopno-copy sharing
  • import cupy as cp a = cp.arange(n, dtype=cp.float32) ptr = a.data.ptr # raw device pointer for launch()★
    Let CuPy own the memory & provide arrays; hand its device pointer to your kernel. The pragmatic combo: CuPy for allocation/IO, CUDA Python to launch custom kernels.
  • # __cuda_array_interface__ (CAI): CuPy, Numba, PyTorch, JAX all speak it★
    The standard protocol for zero-copy GPU-array exchange between libraries. DLPack (from_dlpack) is the newer cross-framework standard.
  • t = torch.as_tensor(cupy_arr, device="cuda") # via DLPack
    Move a buffer between frameworks without a host round-trip.

Math Libs & Ecosystem

Reach for prebuilt GPU math, and know which tool fits the job.

11nvmath-pythonGPU math libraries
  • pip install nvmath-python★
    Pythonic access to NVIDIA's CPU/GPU math libraries (cuBLAS, cuFFT, cuSOLVER, cuRAND, cuDSS) — host, device, and distributed APIs. Separate package (v1.x).
  • import nvmath r = nvmath.linalg.advanced.matmul(a, b) # cuBLASLt, fused epilogues
    High-level ops (matmul with fused bias/activation, FFT) that accept CuPy/PyTorch/NumPy arrays.
  • from nvmath.bindings import cublas, cufft # low-level C bindings too
    nvmath.bindings.* gives raw bindings to the math-library C APIs, matching the cuda.bindings style.
12Choosing a toolthe landscape
  • # want NumPy on the GPU? -> CuPy★
    CuPy is the drop-in NumPy/SciPy for arrays & standard math — most people start here, not with raw CUDA Python.
  • # want to WRITE kernels in Python? -> Numba @cuda.jit or NVIDIA Warp
    CUDA Python launches C++ kernels; to write kernels in Python syntax use Numba (@cuda.jit) or Warp.
  • # need the exact CUDA C API / to build a library? -> cuda.bindings
    CUDA Python's niche: precise control, custom kernel launch, and a stable foundation other GPU libraries build on.
  • # prebuilt BLAS/FFT/solvers -> nvmath-python (or CuPy's wrappers)
    Don't reimplement matmul/FFT — use the tuned math libraries.
