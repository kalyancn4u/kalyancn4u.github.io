Quick Reference · data validation & serialization · v2 · expanded

pydantic · cheat sheet

One idea underneath everything: your type annotations compile to a core schema (in Rust) that does two jobs — validate untrusted input into a typed instance, and serialize that instance back to a dict or JSON. Validators hook the way in; serializers hook the way out. This is v2 — every method is model_*. Expanded edition: nested & generic models, discriminated unions, JSON Schema, custom types, and FastAPI patterns.

One schema, two directions — validate in, serialize out
quickstart · define · validate · serialize
from pydantic import BaseModel, Field, field_validator
from datetime import datetime

class User(BaseModel):
    id: int
    name: str = "anon"
    age: int = Field(gt=0, le=120)          # constraint
    joined: datetime | None = None

    @field_validator("name")
    @classmethod
    def titlecase(cls, v): return v.title()

u = User.model_validate({"id": "1", "name": "ada", "age": 36})
# "1" coerced → 1 ; name → "Ada"
u.model_dump()          # {'id': 1, 'name': 'Ada', 'age': 36, 'joined': None}
u.model_dump_json()     # '{"id":1,"name":"Ada",...}'

Part IIFields & Typesconstrain · annotate · specialize · alias
05Field()defaults & constraints
  • x: int = Field(default=0)★
    Default + metadata in one place.
  • Field(default_factory=list)★
    For mutable defaults — never = []. Also default_factory= that takes validated data.
  • Field(gt=0, le=120, multiple_of=2)★
    Numbers: gt ge lt le multiple_of.
  • Field(min_length=1, pattern=r'^\w+$')
    Strings/collections; max_length, max_digits, decimal_places.
  • Field(union_mode='left_to_right')
    Control how a union field resolves (default 'smart').
  • Field(deprecated=True)
    Marks a field deprecated (warns + shows in schema).
  • Field(description=…, examples=…, json_schema_extra=…)
    Feeds JSON Schema · frozen, exclude, repr, kw_only.
06The Annotated patternreusable metadata
  • x: Annotated[int, Field(gt=0)]★
    Preferred over x: int = Field(...) — composable.
  • Pos = Annotated[int, Field(gt=0)]★
    Name it once, reuse across models.
  • Annotated[str, StringConstraints(strip_whitespace=True, pattern=…)]
    Bundled string rules.
  • Annotated[int, AfterValidator(f), PlainSerializer(g)]
    Stack validators & serializers on the type itself.
  • Annotated[list, Len(1, 10)]
    annotated_types constraints (Gt, Len, MultipleOf) work directly.
07Common field typesstdlib annotations
  • str · int · float · bool · bytes★
    Scalars, coerced by default (lax mode).
  • list[int] · dict[str,int] · set · tuple · frozenset★
    Parametrized containers validate items; Sequence/Mapping for abstract.
  • x: int | None = None★
    Optional value; a | b / Union[a,b] for either.
  • datetime · date · time · timedelta
    Parsed from ISO strings & timestamps.
  • Decimal · UUID · Path · Enum · Literal[…]
    Rich stdlib types work out of the box; Any skips validation.
  • PastDate · FutureDatetime · AwareDatetime
    Temporal constraints as ready-made types.
08Pydantic typesbatteries included
  • EmailStr · HttpUrl · AnyUrl · NameEmail★
    Validated email/URL (pip install pydantic[email]).
  • SecretStr · SecretBytes
    Masked in repr/logs; read via .get_secret_value().
  • PositiveInt · NonNegativeInt · FiniteFloat
    Named constraints, no Field needed.
  • conint(gt=0) · constr(…) · conlist(…)
    Constrained-type factories (Annotated is preferred).
  • Json[list[int]] · Base64Str · ByteSize
    Json[T] parses a JSON-string field; sizes like "1.5GB".
  • PostgresDsn · IPvAnyAddress · ImportString
    DSNs, IPs, and dotted-path imports.
09Custom & arbitrary typesextend the type system
  • Annotated[T, AfterValidator(f)]★
    The easy path — attach logic without a new class.
  • InstanceOf[MyClass]
    Accept an existing instance without deep validation.
  • SkipValidation[int]
    Bypass validation for this field entirely.
  • ConfigDict(arbitrary_types_allowed=True)
    Allow non-pydantic classes as field types.
  • def __get_pydantic_core_schema__(cls, src, handler): ...
    Full control: teach Pydantic to validate your own type.
10Aliasesexternal ↔ field names
  • Field(alias='userId')★
    Applies to both input & output by default.
  • Field(validation_alias='in', serialization_alias='out')
    Different names each direction.
  • AliasChoices('a', 'b')
    Accept any of several input keys.
  • AliasPath('x', 0, 'y')
    Pull from a nested path in the input.
  • ConfigDict(alias_generator=to_camel)★

Part IIIValidateraw input → guaranteed instance
11Validate inputraw → typed instance
  • User(**data)★
    Keyword args — the everyday path.
  • User.model_validate(data_dict)★
    From a dict (or any mapping).
  • User.model_validate_json(json_str)★
    Parse + validate JSON in one Rust-fast step.
  • User.model_validate_strings({'age':'5'})
    All-string input (env/CSV) → coerced by field type.
  • .model_validate(orm, from_attributes=True)
    Read attributes off an ORM/arbitrary object.
  • .model_validate(d, strict=True, context={…})
    Per-call strictness & runtime context for validators.
  • User.model_construct(**d)unsafe
    Build without validation — trusted data only.
12field_validatorper-field logic
  • @field_validator('email')
    @classmethod
    def f(cls, v): ...    ★
    Must be a @classmethod; return the (fixed) value.
  • @field_validator('x', mode='before')★
    before = raw input; after (default) = post-coercion.
  • def f(cls, v, info): info.data
    ValidationInfo exposes already-validated fields & info.context.
  • @field_validator('a', 'b')
    One validator for many fields · '*' = all fields.
  • raise ValueError('bad')★
    Raise ValueError/AssertionError to fail validation.
13model_validatorwhole-model / cross-field
  • @model_validator(mode='after')
    def f(self): return self    ★
    Instance method (uses self); must return self.
  • @model_validator(mode='before')
    @classmethod
    Sees the raw input dict before field parsing.
  • if self.a > self.b: raise ...★
    Cross-field checks live here, not in field_validator.
  • mode='wrap'
    Full control: call (or skip) the inner handler.
14Annotated validatorsreusable, on the type
  • Annotated[int, BeforeValidator(f)]
    Runs before core validation (raw value).
  • Annotated[str, AfterValidator(f)]★
    Runs after — the common case.
  • WrapValidator(f)
    Wraps core validation with a handler you call.
  • PlainValidator(f)
    Replaces core validation entirely.
15Errors & strictnesscoercion control
  • except ValidationError as e:★
    Raised on bad input; catch it around validation.
  • e.errors(include_url=False)★
    List of {type, loc, msg, input, ctx} · e.error_count(), e.json().
  • raise PydanticCustomError('code', 'msg {x}', {'x':v})
    Structured, templated custom errors from validators.
  • # lax default: "5" → 5
    Coercion is on unless you opt out.
  • ConfigDict(strict=True)★
    Forbid coercion model-wide · Field(strict=True) per field.
  • x: StrictInt · StrictStr
    Strict types inline · Strict() in Annotated.

Six ideas that make the rest obvious

Everything above is one of these patterns in disguise. Learn the shapes, not the method list.

one schema, two jobs

Annotations compile to a core schema that both validates input and serializes output. Same schema, opposite directions.

validator modes: before · after · wrap

Where your function sits relative to core coercion. before sees raw input; after sees the coerced value; wrap straddles it.

field_validator vs model_validator

Scope decides which to use: one field's value, or the whole model where you can compare fields.

model_dump flags → different output

One instance, many shapes. The flags decide type, which keys, and which names appear.

discriminated unions dispatch by tag

A literal tag field routes the input straight to one member — no trial-and-error, and errors point at the right model.

lax vs strict coercion

By default Pydantic coerces compatible types. Strict mode refuses — the same input either converts or raises.
