BentoML cheat sheet

BentoML turns a model-inference script into a production REST API with a couple of decorators. Wrap a class in @bentoml.service, mark methods with @bentoml.api, and type-hint the I/O — BentoML gives you a server with validation, docs, adaptive batching, and streaming. Package everything (code + models + env) into a versioned Bento, then containerize to Docker or deploy to BentoCloud. Targets the modern 1.4.x service API (the class-based successor to the old Runner API), Python 3.9+.

Build a Service

A service is a Python class; its methods become validated HTTP endpoints.

1Install & first serviceservice.py
  • pip install bentoml★
    Python 3.9+. Installs the framework + the bentoml CLI. Add framework extras as needed (e.g. bentoml[triton]).
  • import bentoml @bentoml.service class Summarizer: @bentoml.api def summarize(self, text: str) -> str: return do_summary(text)★
    A whole service in one class. Save as service.py; the class name is the service.
  • bentoml serve service:Summarizer★
    Starts a dev server on :3000 with Swagger UI at /. Syntax is <file>:<ClassName>.
  • curl -X POST localhost:3000/summarize -H "Content-Type: application/json" \ -d '{"text":"long text..."}'
    Each @api method becomes a POST /<method> endpoint that takes JSON matching its params.
2@service & @apithe two decorators
  • @bentoml.service(name="summarizer") class S: def __init__(self): self.model = load() # runs once per worker at startup★
    __init__ loads models/state once when the service starts — not per request.
  • @bentoml.api def predict(self, x: int) -> int: ...★
    Only @bentoml.api methods are exposed; helpers stay private. One service can have many endpoints.
  • @bentoml.api(route="/v1/generate")
    Override the URL path. Default route is the method name.
  • with bentoml.importing(): import torch # heavy/optional import, only at runtime
    bentoml.importing() defers imports that shouldn't run at build time (e.g. GPU libs).
3Inputs & outputstype hints = schema
  • @bentoml.api def f(self, name: str, n: int = 1) -> dict: ...★
    Type hints define & validate the request/response schema automatically (via Pydantic under the hood).
  • from pydantic import BaseModel class In(BaseModel): prompt: str; temp: float = 0.7 @bentoml.api def gen(self, params: In) -> str: ...★
    Use a Pydantic model for structured/validated input with defaults & constraints.
  • from PIL import Image import numpy as np def classify(self, img: Image.Image) -> np.ndarray: ...
    Rich types just work: PIL images, numpy arrays, pandas DataFrames, and pathlib.Path for file uploads/downloads.
  • from bentoml import File def transcribe(self, audio: File) -> str: ...
    Accept raw file uploads with the File / Path types; return files the same way.

Serving Features

Stream tokens, batch requests for throughput, and offload long jobs.

4Streaming & batchingthroughput
  • from typing import Generator @bentoml.api def stream(self, p: str) -> Generator[str, None, None]: for tok in gen(p): yield tok★
    Return a generator (or async generator) to stream responses (SSE) — the standard LLM token-streaming pattern.
  • @bentoml.api(batchable=True, batch_dim=0) def embed(self, texts: np.ndarray) -> np.ndarray: ...★
    Adaptive batching: BentoML merges concurrent requests into one batched call to the model, then splits the results — big GPU throughput win.
  • @bentoml.api(batchable=True, max_batch_size=32, max_latency_ms=100)
    Tune the batch window: cap size and the max wait before dispatching a partial batch.
  • async def predict(self, x): ...
    Async endpoints are fully supported for high concurrency and calling other async services.
5Tasks & ASGI mountbeyond request/response
  • @bentoml.task def batch_job(self, items: list) -> str: ...★
    Tasks run long jobs asynchronously: the client submits and polls for status/result instead of blocking on one HTTP call.
  • @bentoml.service class S: app = FastAPI() @bentoml.mount_asgi_app(app, path="/custom")
    Mount a FastAPI/Starlette app for custom routes, health checks, or auth alongside the generated API.
  • def f(self, x, ctx: bentoml.Context): ctx.request.headers
    Add a bentoml.Context param to read request headers/state and set response status/headers.

Models & Config

Version models in the store, size the runtime, and compose services.

6Model storeversion models
  • import bentoml bentoml.sklearn.save_model("iris_clf", clf)★
    Save a trained model to the local store with a name; each save gets an auto version tag (iris_clf:<hash>). Framework modules: pytorch, sklearn, xgboost, transformers, onnx…
  • bento_model = bentoml.models.get("iris_clf:latest") model = bento_model.load_model()★
    Reference a stored model by tag; :latest resolves to the newest. Load it in __init__.
  • @bentoml.service class S: bento_model = bentoml.models.get("iris_clf:latest")
    Declaring a model as a class attribute links it to the service so it's packaged into the Bento automatically.
  • bentoml models list · bentoml models pull · bentoml models push
    Manage the store from the CLI; push/pull models to/from BentoCloud or an S3-backed store.
7Service configresources / scaling
  • @bentoml.service( resources={"gpu": 1, "memory": "4Gi"}, traffic={"timeout": 60})★
    Declare the runtime footprint & request timeout right on the decorator — used when deploying.
  • @bentoml.service(workers=4)
    Number of service worker processes (default: match CPU/GPU). workers="cpu_count" for one per core.
  • @bentoml.service(traffic={"concurrency": 32})
    Max concurrent requests per replica — the key signal for BentoCloud autoscaling.
  • bentoml.serve(..., env={"HF_TOKEN": bentoml.env(...)}) # envs
    Configure environment variables & secrets for the service; also settable in the build config.
8Composition (depends)multi-service
  • @bentoml.service class API: embedder = bentoml.depends(EmbeddingService)★
    bentoml.depends() injects another service. Call it like a local object: await self.embedder.embed(x).
  • # each @service scales independently in one deployment graph
    Compose an inference graph: a GPU model service + a lightweight API service, scaled separately. This replaces the old Runner model.
  • embedder = bentoml.depends(url="http://remote:3000")
    Depend on an already-deployed remote service by URL instead of co-packaging it.

Package & Ship

Freeze code + models + environment into a Bento, then a container.

9Build config (bentofile)reproducible env
  • # pyproject.toml [tool.bentoml.build] service = "service:Summarizer"★1.4
    Modern config lives in pyproject.toml. It names the service and the build environment.
  • [tool.bentoml.build.python] packages = ["torch", "transformers"]★
    Pin Python deps (or point to a requirements.txt/lockfile) so the Bento rebuilds identically anywhere.
  • # bentofile.yaml (classic equivalent) service: "service:Summarizer" python: {packages: [torch]} docker: {python_version: "3.11"}
    The YAML bentofile.yaml is still fully supported. Set base image, system packages, CUDA, etc. under docker:.
  • include: ["*.py"] · envs: [{name: HF_TOKEN}]
    Control which files are packaged and declare required env vars.
10serve, build & containerizeCLI flow
  • bentoml serve service:Summarizer --reload★
    Local dev with hot reload. Add --port/--host as needed.
  • bentoml build★
    Package code + models + env into a versioned Bento in the local store (~/bentos). Reads the build config.
  • bentoml list · bentoml get summarizer:latest · bentoml export/import
    Manage Bentos; export a Bento to a .bento archive to move between machines.
  • bentoml containerize summarizer:latest★
    Turn a Bento into an OCI/Docker image (auto-generated Dockerfile). Run it anywhere: docker run -p 3000:3000 summarizer:latest.

Deploy & Ecosystem

One command to the cloud, plus where BentoML fits with other tools.

11BentoCloud & deployto production
  • bentoml cloud login★
    Authenticate to BentoCloud (the managed serving platform) once.
  • bentoml deploy service:Summarizer★
    Build + push + deploy in one step, with autoscaling (including scale-to-zero) driven by the traffic/resources config.
  • bentoml deployment list · update · terminate
    Manage running deployments from the CLI (or the web console / Python SDK).
  • # self-host: run the container on K8s, or use the bentoctl/operator
    Not on BentoCloud? Deploy the containerized Bento to your own Kubernetes / cloud runtime.
12Ecosystemplays well with
  • # serve any model: PyTorch, TF, sklearn, XGBoost, ONNX, transformers, vLLM★
    Framework-agnostic: wrap your inference code regardless of how the model runs (including an internal vLLM/ONNX engine).
  • # OpenLLM = BentoML-based one-command LLM serving
    OpenLLM builds on BentoML to serve open LLMs with an OpenAI-compatible API.
  • # pairs with MLflow / W&B (training) and Triton (backend)
    Import models tracked elsewhere into the store; use a Triton runner for max GPU performance.
  • bentoml.models.import_model(...) · HF models via transformers
    Bring models from the Hugging Face Hub or other registries into the Bento model store.

The modern flow: @bentoml.service class + @bentoml.api methods with type hints → bentoml build a versioned Bento → containerize or deploy. Adaptive batching, streaming, tasks, and multi-service composition (bentoml.depends) are built in; the pre-1.2 Runner API is legacy.
Star (★) marks the most common operations. Config keys & framework modules evolve — confirm against the current docs & bentoml --help before shipping.
