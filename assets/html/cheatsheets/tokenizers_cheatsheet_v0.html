tokenizers cheat sheet

Hugging Face tokenizers is the Rust-backed library that turns text into model input ids — blazing fast, with full offset tracking back to the original string. It's what powers the "Fast" tokenizers in 🌐 Transformers. A tokenizer is a pipeline: normalizer → pre-tokenizer → model (BPE/WordPiece/Unigram) → post-processor → decoder. Use it to train a new vocabulary or run an existing one. This sheet targets tokenizers 0.2x.

Run an Existing Tokenizer

Load and encode — the common case.

1Install & load0.2x
  • pip install tokenizers★
    Standalone; also ships inside transformers. Prebuilt Rust wheels — no compiler needed.
  • from tokenizers import Tokenizer tok = Tokenizer.from_pretrained("bert-base-uncased")★
    Pull a trained tokenizer straight from the Hub. Tokenizer.from_file("tokenizer.json") for a local one.
  • tok.get_vocab_size() · tok.get_vocab() · tok.token_to_id("the")
    Inspect the vocabulary and map tokens ↔ ids.
2Encode & the Encoding objecttext → ids
  • enc = tok.encode("Hello, world!")★
    Returns an Encoding — the rich result object, not just ids.
  • enc.ids · enc.tokens · enc.attention_mask · enc.type_ids★
    Everything a model needs. enc.ids → the integer input; enc.tokens → the human-readable subwords.
  • enc.offsets # [(start,end), ...] char spans in the original text★
    The killer feature: map each token back to its exact characters — essential for NER/QA span extraction.
  • tok.decode(enc.ids) · tok.encode("A", "B") # sentence pair
    Decode back to text; pass two strings for pair tasks (adds separators via the post-processor).

Build a Tokenizer

Assemble the pipeline from parts.

3The 5-stage pipelinehow a tokenizer works
  • # 1 normalizer 2 pre_tokenizer 3 model 4 post_processor 5 decoder★
    Text flows through these five stages. Each is a swappable component — understanding the order is the whole mental model.
  • from tokenizers import Tokenizer from tokenizers.models import BPE tok = Tokenizer(BPE(unk_token="[UNK]"))★
    Start from the core model (the algorithm that splits into subwords), then attach the other stages.
  • tok.normalizer = ... · tok.pre_tokenizer = ... · tok.decoder = ...
    Set each stage as an attribute. Only the model is required; the rest have sensible no-ops.
4Models, normalizers, pre-tokenizersthe parts
  • from tokenizers.models import BPE, WordPiece, Unigram, WordLevel★
    Model: BPE (GPT), WordPiece (BERT), Unigram (T5/SentencePiece), WordLevel (whole words).
  • from tokenizers import normalizers tok.normalizer = normalizers.Sequence([NFD(), Lowercase(), StripAccents()])★
    Normalizer: clean text (unicode, casing, accents) before splitting. Chain with Sequence.
  • from tokenizers import pre_tokenizers tok.pre_tokenizer = pre_tokenizers.Whitespace() # or ByteLevel(), Metaspace()★
    Pre-tokenizer: initial split into words. ByteLevel (GPT-style, handles any byte) is common for BPE.
  • pre_tokenizers.Sequence([Whitespace(), Digits(individual_digits=True)])
    Compose pre-tokenizers too — e.g. split off digits individually for number-heavy text.

Train

Learn a vocabulary from your corpus.

5Train a vocabularytrainers
  • from tokenizers.trainers import BpeTrainer trainer = BpeTrainer(vocab_size=30000, special_tokens=["[UNK]","[CLS]","[SEP]","[PAD]","[MASK]"])★
    One trainer per model type (BpeTrainer, WordPieceTrainer, UnigramTrainer, WordLevelTrainer).
  • tok.train(["corpus1.txt", "corpus2.txt"], trainer)★
    Train from files. Fast — millions of lines in seconds thanks to the Rust core.
  • tok.train_from_iterator(text_generator, trainer, length=n)★
    Train from any Python iterator (a 🌐 datasets stream, a generator) — no need to dump to disk.
  • BpeTrainer(..., min_frequency=2, show_progress=True)
    Drop rare merges; initial_alphabet / ByteLevel.alphabet() to guarantee full byte coverage.
6Post-processing & decodersspecial tokens & text back
  • from tokenizers.processors import TemplateProcessing tok.post_processor = TemplateProcessing( single="[CLS] $A [SEP]", pair="[CLS] $A [SEP] $B:1 [SEP]:1", special_tokens=[("[CLS]", cls_id), ("[SEP]", sep_id)])★
    Post-processor: insert [CLS]/[SEP] and set type ids. $A/$B are the sequences; :1 = type id.
  • from tokenizers import decoders tok.decoder = decoders.ByteLevel() # or WordPiece(), Metaspace()
    Decoder: correctly join subwords back to text (must match the pre-tokenizer's scheme).

Use & Integrate

Batches, alignment, and handing off to Transformers.

7Padding, truncation, batchesfor the model
  • tok.enable_padding(pad_id=0, pad_token="[PAD]")★
    Pad a batch to the longest item (or length= for fixed). Set on the tokenizer, applies to all encodes.
  • tok.enable_truncation(max_length=512)★
    Cap length; strategy controls which sequence gets cut in pairs.
  • encs = tok.encode_batch(["a", "b", "c"])★
    Batch-encode a list (parallelized in Rust) — returns a list of Encodings.
  • tok.encode(text, add_special_tokens=False)
    Skip the post-processor's special tokens for a raw tokenization.
8Offsets & alignmenttoken ↔ char
  • enc.word_ids · enc.words # which word each token belongs to★
    Group subwords back into words — needed to align token-level predictions with word-level labels (NER).
  • enc.char_to_token(pos) · enc.token_to_chars(i)★
    Two-way mapping between character positions and token indices — extract the exact answer span in QA.
  • enc.token_to_word(i) · enc.word_to_tokens(w)
    Token↔word alignment for label projection across the subword boundary.
9Save & use in Transformersship it
  • tok.save("tokenizer.json")★
    The entire pipeline (model + all stages) serializes to one JSON file. Tokenizer.from_file(...) to reload.
  • from transformers import PreTrainedTokenizerFast hf = PreTrainedTokenizerFast(tokenizer_object=tok)★
    Wrap it for the Transformers API (returns dicts of tensors, plays with the Trainer). Set pad_token etc.
  • hf.save_pretrained("my-tok/"); hf.push_to_hub("me/my-tok")
    Publish so it loads via AutoTokenizer.from_pretrained alongside a model.
!Common gotchasread before shipping
  • decoder must match pre-tokenizer
    A ByteLevel pre-tokenizer needs a ByteLevel decoder (etc.) or decode() produces garbled spacing.
  • add special tokens in the vocab AND post-processor
    [CLS]/[SEP] must be in the trainer's special_tokens and referenced by the post-processor's template.
  • this library ≠ SentencePiece
    Unigram here is compatible in spirit, but existing .model SentencePiece files aren't loaded directly — convert or retrain.
  • offsets are on the normalized text unless configured
    Some normalizers change lengths; keep track (or use ByteLevel(add_prefix_space) settings) so char offsets line up with your raw input.
