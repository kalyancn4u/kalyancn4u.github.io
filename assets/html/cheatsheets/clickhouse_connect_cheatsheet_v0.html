ClickHouse Connect cheat sheet

clickhouse-connect is ClickHouse's official Python driver, talking to the server over HTTP(S). Make a client with get_client(), then query() for rows, query_df() for a pandas DataFrame, insert() / insert_df() to write, and command() for DDL. It has first-class pandas, NumPy, and Arrow support, streaming for huge result sets, an async client, and powers the ClickHouse SQLAlchemy dialect & Superset connector. Targets clickhouse-connect 1.x, Python 3.9+.

Connect & Query

Open an HTTP client, run SQL, and get rows or a DataFrame back.

1Install & get_clientHTTP driver
  • pip install clickhouse-connect★
    Optional extras: [numpy], [pandas], [arrow], [async], [sqlalchemy]. Python 3.9+.
  • import clickhouse_connect client = clickhouse_connect.get_client( host="localhost", port=8123, username="default", password="")★
    The entry point. Default HTTP port is 8123; for TLS use secure=True (port 8443).
  • client = clickhouse_connect.get_client( host="<id>.clickhouse.cloud", secure=True, password="...")
    ClickHouse Cloud: secure=True + host from the console. Add database= to set the default DB.
  • client.ping() · client.server_version
    Verify the connection. client.close() when done (or use it as a context manager).
2Query rows.query()
  • res = client.query("SELECT id, name FROM t WHERE id > 10")★
    Returns a QueryResult. res.result_rows = list of row tuples; res.column_names = the headers.
  • for row in res.result_rows: print(row) # (id, name)★
    Iterate rows as tuples. res.result_columns gives column-oriented data instead.
  • client.query("SELECT count() FROM t").result_rows[0][0]
    Pull a single scalar. res.summary has rows-read / bytes-read stats.
  • rows = client.query_np("SELECT * FROM t") # NumPy array
    query_np returns a NumPy structured array — efficient for numeric analytics.
3Query to DataFrame / Arrowanalytics
  • df = client.query_df("SELECT * FROM t WHERE ts >= today()")★
    query_df returns a pandas DataFrame directly — the most common analytics path. Needs the pandas extra.
  • tbl = client.query_arrow("SELECT * FROM t") # pyarrow.Table★
    query_arrow returns an Arrow Table — zero-copy handoff to Polars/DuckDB/Parquet.
  • for df in client.query_df_stream("SELECT * FROM big"): process(df)
    Stream results as a sequence of DataFrame blocks — constant memory over huge tables (card 9).

Insert

Write rows, DataFrames, or Arrow tables — in big batches, the ClickHouse way.

4Insert rows.insert()
  • client.insert("t", [[1,"a"],[2,"b"]], column_names=["id","name"])★
    Insert a list of row lists. Pass column_names so the driver maps & type-checks correctly.
  • client.insert("t", data, column_names=[...], column_type_names=["UInt32","String"])
    Give explicit types when the driver can't infer them (e.g. from empty/ambiguous data).
  • # insert ONE big batch, not a row per callgotcha
    ClickHouse hates tiny inserts (each makes a part). Batch thousands+ of rows per insert(); let async-insert or a buffer handle high-frequency streams.
  • client.command("INSERT INTO t VALUES (1,'a')")
    For a one-off literal insert you can also just run the SQL via command() — but insert() is faster for data.
5Insert DataFrame / Arrowbulk load
  • client.insert_df("t", df)★
    Insert a pandas DataFrame — columns are matched to table columns by name. The fastest way to load a DataFrame.
  • client.insert_arrow("t", arrow_table)★
    Insert a pyarrow Table directly — efficient columnar load, great from Parquet.
  • client.insert_df("t", df, settings={"async_insert":1})
    Per-insert settings (e.g. enable server-side async inserts for many small writes).

DDL & Types

Run statements, bind parameters, and hand ClickHouse's rich types to Python.

6command() & DDLstatements
  • client.command(""" CREATE TABLE t (id UInt32, name String, ts DateTime) ENGINE = MergeTree ORDER BY (ts, id)""")★
    command() runs DDL/DCL and statements that don't return a result set. MergeTree + ORDER BY is the standard table shape.
  • client.command("DROP TABLE IF EXISTS t") client.command("TRUNCATE TABLE t") · "OPTIMIZE TABLE t FINAL"
    Lifecycle statements. command returns a scalar/summary for single-value queries.
  • n = client.command("SELECT count() FROM t")
    command is a convenient shortcut when you expect exactly one value back.
7Parameters & settingssafe SQL
  • client.query("SELECT * FROM t WHERE id = {id:UInt32}", parameters={"id": 42})★
    Server-side bound parameters with {name:Type} placeholders — safe against SQL injection. Types are ClickHouse types.
  • client.query(sql, settings={"max_execution_time":60, "max_threads":4})★
    Pass any ClickHouse query setting per call (timeouts, memory limits, formats). Set defaults on get_client(settings=...).
  • client.query(sql, query_id="my-job-1")
    Tag a query to find/kill it in system.processes.
8Types & formatsmapping
  • # UInt/Int/Float, String, DateTime(64), Date, Decimal, UUID, IPv4/6
    Rich scalar types map to Python natively. Nullable(T) → None; LowCardinality(T) is transparent.
  • # Array(T) -> list · Map(K,V) -> dict · Tuple -> tuple · Nested
    Composite types round-trip to the obvious Python containers.
  • client.query(sql, column_formats={"ts": "int"})
    Override how a column is materialized (e.g. datetimes as ints/strings, UUIDs as strings) via column_formats/query_formats.
  • # DateTime is timezone-aware — mind the server/session TZgotcha
    ClickHouse stores DateTime in UTC and applies a column/session timezone on read — be explicit about TZ to avoid off-by-hours bugs.

Streaming & Async

Read results larger than memory, and go concurrent.

9Streaming large resultsbounded memory
  • with client.query_row_block_stream("SELECT * FROM big") as stream: for block in stream: for row in block: ...★
    Stream native row blocks so you never hold the whole result in memory. Use it in a with block to release the connection.
  • for df in client.query_df_stream(sql): ... for tbl in client.query_arrow_stream(sql): ...★
    Streaming variants for DataFrame and Arrow blocks — the practical way to ETL big tables.
  • stream = client.query_rows_stream(sql) # row-at-a-time iterator
    Finer-grained streaming iterators exist too; all keep memory flat.
10Async clientconcurrency
  • client = await clickhouse_connect.get_async_client(host="...") res = await client.query("SELECT 1")★
    get_async_client() gives an awaitable client with the same method names — ideal inside asyncio/FastAPI. Needs the [async] extra.
  • await client.insert_df("t", df) · await client.command(...)
    Query/insert/command all have async forms. (It wraps the sync driver on a thread pool by default.)

Config & Ecosystem

Tune the HTTP layer, and see where the driver plugs in.

11Config & ecosystemthe wider stack
  • get_client(compress=True, connect_timeout=10, query_limit=0, pool_mgr=..., settings={...})★
    Tune HTTP: compress (lz4/zstd), timeouts, connection pool, and query_limit (0 = unlimited rows).
  • get_client(dsn="clickhouse://user:pass@host:8443/db?secure=true")
    Configure from a single DSN URL — handy for env-var config.
  • # SQLAlchemy: clickhouse-connect ships the SQLAlchemy dialect + Superset
    The same package backs the ClickHouse SQLAlchemy dialect and the Apache Superset connector.
  • # clickhouse-connect (HTTP) vs clickhouse-driver (native TCP :9000)
    This is the HTTP driver (official, cloud-friendly, Arrow/pandas-first). clickhouse-driver uses the native TCP protocol — lower overhead, but HTTP is the recommended default.
