Quick Reference · experiment visualization in Python · TensorBoard 2.21 (Jun 2026)

tensorboard tf.summary · Keras · PyTorch

Nothing in TensorBoard is live. Your code appends records to event files in a log directory; TensorBoard is a web server that polls that directory and redraws whatever it finds. The blank dashboard, the duplicated run, the plot that stopped updating — every one of them is a question about those files, not about the UI.

Where the numbers actually go
# --- write (TensorFlow / Keras) -------------------------------
import tensorflow as tf, keras, datetime
logdir = "logs/fit/" + datetime.datetime.now().strftime("%Y%m%d-%H%M%S")
cb = keras.callbacks.TensorBoard(log_dir=logdir, histogram_freq=1)
model.fit(ds, epochs=10, validation_data=val, callbacks=[cb])

# --- write (PyTorch) ------------------------------------------
from torch.utils.tensorboard import SummaryWriter
w = SummaryWriter("runs/exp1")
w.add_scalar("loss/train", loss.item(), global_step)   # step is required
w.close()                                              # or nothing appears

# --- read -----------------------------------------------------
tensorboard --logdir logs --port 6006          # parent dir, not a run
Write, flush, point at the parent directory. The rest of this sheet is detail.
PART I

the tool  ·  launching and reading

TensorBoard is a reader. It has no opinion about how the files got there and no dependency on TensorFlow — pip install tensorboard alone is enough to visualise runs written by PyTorch, JAX or anything else that emits the event format. Since TF 2.21 it is no longer installed with TensorFlow.
01Install & launchsixty seconds
  • pip install tensorboard★TF 2.21
    No longer bundled with TensorFlow as of TF 2.21 — install it yourself.
  • tensorboard --logdir logs★
    Serves on localhost:6006. Leave it running; it re-reads the directory as you train.
  • tensorboard --logdir logs --port 6007
    When 6006 is taken, which it usually is.
  • it does not need TensorFlow
    A pure reader of the event format. PyTorch- and JAX-only environments are fine.
  • python -m tensorboard.main --logdir logs
    When the console script is not on PATH.
  • pip install tensorboard-data-server
    Enables --load_fast=true, a much faster loader for large directories.
  • tensorboard --version_tb
    Current release is 2.21.0 (Jun 2026), Python 3.9+.
  • the tab says “No dashboards are active”★
    Almost never a broken install. It means no data of that type was found — wrong --logdir, or nothing flushed yet.
02The log directorythe only real concept
  • one subdirectory = one run★
    And one run = one line per tag on every chart. Internalise this and the UI stops surprising you.
  • logs/fit/<timestamp>/train · /validation★
    The conventional layout. Two writers, two runs, two colours, compared automatically.
  • events.out.tfevents.<time>.<host>.<pid>.v2
    The file itself — append-only, one per writer.
  • --logdir points at the parent
    Point it at a single run and you lose every comparison.
  • the run name is the relative path
    So directory naming is chart naming. Name deliberately: lr0.001_bs32/ beats run7/.
  • --logdir_spec baseline:./a,tuned:./b
    Explicit names for directories that are not siblings. Disables some features — prefer a common parent.
  • gs://bucket/logs · s3://bucket/logs
    Cloud paths work directly, given credentials.
  • re-running into the same directory★classic
    The old events stay. Steps restart at zero and the line zigzags backwards. Use a fresh timestamped directory.
03Flags that matterthe CLI
  • --bind_all★
    Listen on every interface so another machine can reach it. Off by default, deliberately.
  • --host 0.0.0.0 --port 6006
    The explicit form of the same thing.
  • --reload_interval 5★
    Seconds between directory scans. 0 loads once and never refreshes.
  • --samples_per_plugin scalars=2000,images=100★surprising
    TensorBoard downsamples by default — roughly 1000 scalar points per tag. Your chart is a sample, not the data.
  • --load_fast=true
    The Rust data server. Much faster on big directories; needs tensorboard-data-server.
  • --path_prefix /tb
    For serving behind nginx or a Jupyter proxy.
  • --reload_multifile=true
    Reads every event file in a run, not just the newest — needed for multi-worker jobs.
  • --purge_orphaned_data=false
    Keeps data written after a restart instead of discarding it.
04Notebooks & Colabinline
  • %load_ext tensorboard★
    Once per kernel.
  • %tensorboard --logdir logs★
    Renders inline in the notebook. Same flags as the CLI.
  • from tensorboard import notebook; notebook.list()
    Which instances are already running.
  • notebook.display(port=6006, height=800)
    Re-show an existing instance rather than starting another.
  • !rm -rf ./logs/
    Clear before re-running a demo cell, or old runs pile up in the selector.
  • several %tensorboard calls
    Each may start a new server on a new port. Reuse with notebook.display.
05Remote & sharedoff your laptop
  • ssh -L 6006:localhost:6006 user@host★
    The safe default. Run TensorBoard on the remote box, tunnel the port, browse locally.
  • tensorboard --logdir logs --bind_all
    Exposes it on the network. Convenient, and unauthenticated — know your network.
  • TensorBoard has no authentication★security
    Anyone who can reach the port sees your runs. Never --bind_all on a public host.
  • docker run -p 6006:6006 -v $PWD/logs:/logs
    Mount the directory; run the server inside.
  • VS Code forwards the port automatically
    Launch it in the integrated terminal over SSH and click the link.
  • rsync -a host:logs/ ./logs/
    Or just copy the event files down and read them locally.
06The dashboardswhat each tab is
  • Time Series★
    The default since 2.10. Scalars, histograms and images together, with per-card pinning and regex filters.
  • Scalars
    The older, simpler chart view. Still there, still fine.
  • Graphs
    The model as a computation graph. Op-level and conceptual views.
  • Distributions · Histograms
    Two renderings of the same weight-over-time data.
  • Images · Audio · Text
    Any media you logged, with a step slider.
  • HParams · Projector · PR Curves · Mesh
    The plugin dashboards — Part III.
  • tabs appear only when data exists★
    A missing tab means a missing summary type, not a broken TensorBoard.
  • the inactive-plugin dropdown
    Top right — lists what is hidden and why.
07Reading a chartthe controls
  • smoothing slider★
    An exponential moving average. The faint line is the truth; the bold one is the smoothing.
  • STEP · RELATIVE · WALL★
    Three x-axes. Step for comparing training progress, relative for comparing speed, wall for debugging a schedule.
  • tag names group by slash
    loss/train and loss/val land in one collapsible loss group.
  • tooltip sorting: nearest · descending
    Under settings. “Nearest” is far more readable with many runs.
  • log scale on y
    The toggle under each chart. Essential for a loss that spans orders of magnitude.
  • ignore outliers in chart scaling
    On by default, which can hide a genuine spike. Worth turning off when hunting one.
  • pin a card
    Pinned cards float to the top of Time Series — your custom dashboard.
  • smoothing distorts the ends★
    The EMA has no history at the start and no future at the end. Never read a final value off a smoothed curve.
08Comparing runsthe actual job
  • the run selector regex★
    Filters by run name. This is why directory naming matters.
  • toggle runs on and off
    Click a name to isolate it; colours stay stable so charts remain comparable.
  • the tag filter box★
    A regex over tag names — ^loss to see only losses.
  • write hyperparameters into the run name
    lr0.001_bs32_adamw/ makes the legend self-documenting without the HParams plugin.
  • Show data download links
    Adds CSV and JSON export under every chart.
  • one writer per condition
    Train and validation as separate runs is what makes the two curves overlay correctly.
  • comparing runs with different step semantics★
    Per-batch steps against per-epoch steps produces a meaningless chart. Fix the step, not the axis.
09Graphsthe model, drawn
  • write_graph=True in the Keras callback★
    On by default. Costs disk on large models.
  • tf.summary.trace_on(graph=True) … trace_export(name, step)★
    How you capture the graph of an arbitrary @tf.function.
  • Op-level vs Conceptual
    Op-level is what actually runs; conceptual is the Keras layer structure you wrote.
  • writer.add_graph(model, example_input)
    The PyTorch route — it traces the model with that batch.
  • colour by structure or by device
    The device view is how you confirm ops landed on the GPU.
  • the graph plugin is Keras 2 eraKeras 3
    With Keras 3 the graph may be sparse or missing. The dashboards for scalars and images are unaffected.
10Images, audio, textnon-scalar logging
  • tf.summary.image(name, tensor, step=i, max_outputs=3)★
    Needs a 4-D tensor (N, H, W, C). A single image must be reshaped first.
  • writer.add_image(tag, img, step)★layout
    PyTorch is CHW, not HWC. add_images takes NCHW.
  • writer.add_figure(tag, matplotlib_fig, step)
    The easiest way to log a confusion matrix or any custom plot.
  • tf.summary.text(name, md_string, step=i)
    Rendered as Markdown — good for config dumps and sample generations.
  • tf.summary.audio(name, tensor, sample_rate, step)
    Shape (batch, frames, channels), float in [-1, 1].
  • the step slider
    Every media dashboard has one. It is how you watch generated samples improve.
  • logging images every step★
    The fastest way to fill a disk. Log every N steps, and cap max_outputs.
11Histograms & distributionswatching the weights
  • histogram_freq=1 in the Keras callback★
    Off by default. Nothing appears in these tabs until you set it.
  • writer.add_histogram(name, param, step)★
    The PyTorch equivalent — loop over model.named_parameters().
  • OVERLAY vs OFFSET
    Overlay stacks the curves for comparison; offset gives the classic ridgeline over time.
  • Distributions = the same data as percentiles
    Bands showing where the bulk of the weights sit. Easier to read at a glance than the histogram.
  • what you are looking for
    A distribution that collapses to zero (dead units) or widens without bound (divergence).
  • histograms are expensive
    They serialise every weight at every logged epoch. Turn them on to diagnose, off to train.
12Housekeepingdisk and staleness
  • a fresh timestamped directory per run★
    The single habit that prevents most TensorBoard confusion.
  • du -sh logs/*
    Find the run that is eating the disk. It is almost always images or histograms.
  • the chart stopped updating★
    Check, in order: the writer was flushed, the process is alive, --reload_interval, then the browser cache.
  • hard-refresh the browser
    TensorBoard caches aggressively. Ctrl-Shift-R resolves a surprising number of “bugs”.
  • kill stale servers
    lsof -i :6006, or pkill -f tensorboard when ports pile up.
  • keep event files, delete checkpoints
    Event files are small and are your experiment record. Checkpoints are what fill the disk.
PART II

writing events  ·  from your code

Three APIs, one file format. tf.summary is the native one, the Keras callback wraps it, and PyTorch ships its own writer producing identical files. Whichever you use, the same two rules apply: every record needs an explicit step, and nothing is visible until it is flushed.
W1tf.summary · the writeropen, write, flush
  • writer = tf.summary.create_file_writer("logs/train")★
    One writer per run directory. Create it once, outside the loop.
  • with writer.as_default():★
    Sets the ambient writer. Every tf.summary.* call inside goes to it.
  • tf.summary.scalar("loss", value, step=i)★
    step is not optional. Omit it and you get an error, not a default.
  • writer.flush()#1
    Forces the buffer to disk. The single most common reason a dashboard is empty.
  • create_file_writer(dir, max_queue=10, flush_millis=120000)
    The buffer thresholds. The default two-minute flush is why short scripts appear to log nothing.
  • writer.close()
    Flushes and releases the file. A with block does it for you.
  • two writers, two runs
    logs/train and logs/val — that is how you get two curves on one chart.
W2tf.summary · what you can logthe record types
  • tf.summary.scalar(name, value, step)★
    Anything reducible to one number.
  • tf.summary.image(name, tensor4d, step, max_outputs=3)★
    Four dimensions, always. tf.expand_dims a single image first.
  • tf.summary.histogram(name, tensor, step, buckets=30)
    Weight and activation distributions.
  • tf.summary.text(name, markdown, step)
    Config, prompts, generated samples.
  • tf.summary.audio(name, tensor, sample_rate, step)
    Waveforms with an inline player.
  • tf.summary.graph(func.get_concrete_function().graph)
    Explicit graph export.
  • tf.summary.write(tag, tensor, step)
    The raw escape hatch when no typed helper fits.
  • name the tag with slashes★
    "loss/train", "grad_norm/layer1" — grouping is free and makes the UI navigable.
W3Steps & conditional loggingcontrolling volume
  • tf.summary.experimental.set_step(i)★
    Set it once per iteration and drop step= from every call.
  • with tf.summary.record_if(lambda: step % 100 == 0):★
    Log every hundredth step without an if around every call — and it works inside a traced function.
  • the default writer is thread-local
    A writer set in one thread is invisible in another. Multi-worker code must set it per worker.
  • inside @tf.function, step must be a tensor
    Pass tf.cast(optimizer.iterations, tf.int64) rather than a Python int.
  • with tf.name_scope("train"):
    Prefixes every tag written inside it.
  • logging every step of a fast loop
    The event file outgrows the checkpoints, and TensorBoard downsamples it away anyway.
W4The Keras callbackthe one-liner
  • keras.callbacks.TensorBoard(log_dir=logdir)★
    Writes loss and every compiled metric, for train and validation, as two runs.
  • log_dir="logs/fit/" + strftime("%Y%m%d-%H%M%S")★
    The timestamp habit. Without it every run lands on top of the last.
  • histogram_freq=1
    Enables the Histograms and Distributions tabs. Zero (the default) leaves them empty.
  • update_freq="epoch" | "batch" | 100
    Per epoch is the sane default; a number means every N batches.
  • write_graph=True · write_images=False
    Graph on by default; weight images off.
  • profile_batch=(10, 20)
    Captures a profile over those steps — needs XProf installed. See P4.
  • embeddings_freq=1
    Populates the Projector from your embedding layers.
  • extra metrics need extra logging★
    The callback only sees what compile(metrics=...) produced. Anything else you write yourself.
W5Custom loopsdoing it by hand
  • train_w, val_w = create_file_writer(d+"/train"), create_file_writer(d+"/val")★
    Two writers up front. This is the whole trick.
  • metric.result() → log → metric.reset_state()★
    Log the epoch aggregate, then reset. Forgetting the reset averages across all of training.
  • log the learning rate too
    optimizer.learning_rate — a schedule that is not doing what you think is a common silent bug.
  • log gradient norms
    tf.linalg.global_norm(grads) tells you about instability long before the loss does.
  • writer.flush() at epoch end
    Cheap, and makes the dashboard track your run in real time.
  • log a sample of predictions as images
    The fastest way to notice that your labels are misaligned.
W6PyTorch · SummaryWriterthe other native writer
  • from torch.utils.tensorboard import SummaryWriter★
    Ships with PyTorch. Still requires the tensorboard package to be installed.
  • w = SummaryWriter("runs/exp1")★
    No argument gives runs/<timestamp>_<hostname> — unique, and unreadable in a legend.
  • w.add_scalar("loss/train", value, global_step)★
    Value must be a Python number or a scalar tensor — call .item().
  • w.add_scalars("loss", {"train": a, "val": b}, step)
    Convenient, but it writes hidden sub-runs. Two writers is the cleaner pattern.
  • w.flush() · w.close()
    Close it. A script that exits without closing frequently loses its last records.
  • with SummaryWriter(dir) as w:
    Context manager, so the close cannot be forgotten.
  • comment="_lr0.001"
    Appended to the auto-generated directory name.
W7PyTorch · the rest of add_*beyond scalars
  • w.add_image(tag, img_chw, step)★layout
    CHW. Pass HWC and you get a garbled image with no error.
  • w.add_images(tag, batch_nchw, step)
    A batch at once; or build a grid with torchvision.utils.make_grid.
  • w.add_figure(tag, fig, step)★
    Any matplotlib figure — confusion matrices, attention maps.
  • w.add_histogram(name, param, step)★
    Loop model.named_parameters() and log weights and gradients.
  • w.add_graph(model, example_batch)
    Traces the model. Fails on genuinely dynamic control flow.
  • w.add_embedding(mat, metadata=labels, label_img=imgs)
    Populates the Projector with almost no ceremony.
  • w.add_hparams({...}, {...})
    Writes a nested run. See P1 for the caveat.
  • w.add_pr_curve · add_text · add_audio · add_video · add_mesh
    The long tail, all with the same signature shape.
W8Other frameworksit is just event files
  • Lightning: TensorBoardLogger(save_dir) + self.log()★
    Logger plus self.log("val_loss", v) and the rest is handled.
  • Transformers: report_to="tensorboard", logging_dir=★
    Set both in TrainingArguments; also logging_steps.
  • pip install tensorboardX
    An independent writer predating the official one. Still maintained (2.6.5), useful outside PyTorch.
  • JAX / Flax
    Either tensorboardX, or tf.summary if TensorFlow happens to be installed.
  • scikit-learn, XGBoost, anything
    Nothing stops you opening a writer and logging your own numbers.
  • two libraries writing one directory
    Duplicate tags and interleaved steps. One writer owns one directory.
PART III

plugins  ·  past the loss curve

The dashboards that need their own API, plus the two things worth knowing about the ecosystem: the profiler has left — tensorboard_plugin_profile is now XProf under OpenXLA, installable and runnable on its own — and TensorBoard.dev has been shut down, so sharing runs means self-hosting or a third-party service.
P1HParamswhich settings won
  • from tensorboard.plugins.hparams import api as hp★
    The plugin ships with TensorBoard — no extra install.
  • HP_LR = hp.HParam("lr", hp.Discrete([1e-3, 1e-4]))★
    Declare the search space. RealInterval and IntInterval also exist.
  • with writer.as_default(): hp.hparams({HP_LR: 1e-3})
    Written once per run, into that run's own directory, before training starts.
  • one directory per trial
    logs/hparam/run-0, run-1… The plugin joins the config to the metrics by run.
  • hp.KerasCallback(logdir, hparams)
    Pass it alongside the TensorBoard callback and the wiring is done.
  • TABLE VIEW · PARALLEL COORDINATES · SCATTER
    Three views. Parallel coordinates is the one that actually shows interactions.
  • filter and sort by metric in the UI
    Sort by val_accuracy, then read the columns that co-vary.
  • PyTorch add_hparams writes a nested run★
    It creates a sub-directory, so the same metrics can appear twice. Log hparams to their own writer if it bothers you.
P2Embedding Projectorhigh-dimensional space
  • w.add_embedding(mat, metadata=labels, label_img=thumbs)★
    By far the easiest route, even if the rest of your stack is TensorFlow.
  • from tensorboard.plugins import projector
    The TF route: write a checkpoint, a metadata file and a config.
  • metadata.tsv — one label per line★
    Row order must match the embedding matrix exactly. A header is required only when there are two or more columns.
  • projector.ProjectorConfig() → visualize_embeddings(logdir, config)
    Writes projector_config.pbtxt next to the checkpoint.
  • PCA · t-SNE · UMAP in the browser★
    Computed client-side, live. t-SNE animates as it converges.
  • sprite images
    One packed image grid lets you see thumbnails instead of dots.
  • tens of thousands of points
    The projector slows to a crawl. Subsample before you write.
P3PR curves & custom scalarsthe quieter plugins
  • w.add_pr_curve(tag, labels, predictions, step)★
    Precision-recall across thresholds, with a slider over training steps.
  • the threshold slider
    Lets you pick an operating point visually rather than guessing.
  • tensorboard.plugins.custom_scalar.summary
    Define a layout: which tags share a chart, and margin plots for confidence bands.
  • margin plots★
    Lower, middle and upper tags drawn as a shaded band — the way to show variance across seeds.
  • the layout is written once
    A single summary at step 0 configures the whole dashboard.
P4XProf · the profilerit left TensorBoard
  • pip install xprof★renamed
    Formerly tensorboard_plugin_profile. Renamed XProf, moved under OpenXLA, and now released on its own cadence.
  • JAX · PyTorch/XLA · TensorFlow, equally★
    No longer a TensorFlow-first tool. That is the point of the move.
  • it also runs standalone
    TensorBoard is now just a container for it — same UI either way, pointed at the same directory.
  • install it and a Profile tab appears
    No configuration. Absent tab means absent package.
  • profile_batch=(10, 20) in the Keras callback
    The easiest capture. Profile a few steps in the middle, never the first.
  • tf.profiler.experimental.start(logdir) … stop()
    Manual capture around any region of code.
  • logdir/plugins/profile/<session>/*.xplane.pb
    The layout XProf expects. Each session becomes an entry in the dropdown.
  • Trace Viewer · Input Pipeline · Memory · HLO op profile
    Gaps in the GPU timeline mean the input pipeline is starving it.
  • it needs internet for Google Charts★offline
    Fully offline or behind a strict firewall, some charts and tables silently fail to render.
P5Reading the data backout of the UI
  • pip install tbparse → SummaryReader(logdir).scalars★
    Straight to a pandas DataFrame, across every run. The pragmatic choice for a paper table.
  • from tensorboard.backend.event_processing.event_accumulator import EventAccumulator★
    The official reader, bundled with TensorBoard.
  • ea = EventAccumulator(path); ea.Reload(); ea.Tags()
    Reload() is mandatory — without it every accessor returns empty.
  • ea.Scalars("loss/train") → [(wall_time, step, value)…]
    Named tuples, ready for a DataFrame.
  • size_guidance={…: 0}
    Load everything instead of the default in-memory downsample.
  • Show data download links → CSV / JSON
    For one chart, the UI export is faster than any script.
  • the chart is downsampled, the file is not★
    If you scrape the UI you get roughly a thousand points. Read the event file for the full series.
P6The remaining tabsMesh, Debugger, What-If
  • Mesh
    3-D point clouds and meshes. add_mesh in PyTorch, mesh_summary in TF.
  • Debugger V2★
    Traces NaNs and infinities back to the originating op. Enable with tf.debugging.experimental.enable_dump_debug_info.
  • What-If Tool · Fairness Indicators
    Model-probing plugins, installed separately. Largely superseded by standalone tooling.
  • writing your own plugin
    A Python backend plus a frontend bundle. Rare, and documented in the TensorBoard repo.
  • the inactive-plugin list★
    Top-right dropdown — the definitive answer to “why is that tab missing”.
P7What is gone, and what elsethe honest ending
  • TensorBoard.dev — shut down★dead
    The free hosted sharing service is dead. tensorboard dev upload now fails immediately without contacting anything.
  • uploaded experiments are not retrievable
    Any tutorial ending in a tensorboard.dev link is showing you a dead end.
  • sharing now means self-hosting★
    Run it on a VM behind your own auth, or export the numbers and publish those.
  • Weights & Biases · MLflow · Aim · Neptune · ClearML
    The hosted alternatives, all with run comparison, artifacts and teams.
  • most of them also read TensorBoard files
    Migration is usually pointing the tool at your existing logs/.
  • when TensorBoard is still the right answer
    Local, offline, free, no account, no upload, and already installed. For a single machine it is hard to beat.

Four pictures worth the whole reference

Where runs come from, the three x-axes, what smoothing really does, and why the dashboard is empty.

1 · directories become runs

TensorBoard walks the tree below --logdir. Every directory containing event files becomes one run, named by its path relative to the root — which is why folder naming is chart naming.

2 · the three x-axes

The same two runs, plotted three ways. Step compares learning; relative compares speed; wall reveals the gap where the job was queued.

3 · what smoothing does

The slider applies an exponential moving average and draws the raw series faintly behind it. It is a reading aid, not data — and at both ends it is wrong.

4 · why the dashboard is empty

Records sit in a buffer until max_queue fills, flush_millis elapses, or you flush. A short script can finish, exit, and leave everything unwritten.
