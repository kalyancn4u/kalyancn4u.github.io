  Arrow Dtypes" card and a "Performance & Gotchas" card. Good shape; targeted fixes.
ADD (headline 3.0 changes, from official whatsnew):
  - NEW DEFAULT str dtype: string columns now infer dtype 'str' (PyArrow-backed if
    pyarrow installed, else object) instead of 'object' — 5–10x faster string ops,
    can only hold strings, missing sentinel is NaN. This is THE user-facing 3.0 change
    and the sheet does not show `dtype: str`. Add to "Nullable & Arrow Dtypes"/dtypes.
  - Nullable dtypes: NaN now treated as NA by default (e.g. Float64 `ser/0` -> <NA>);
    escape hatch `pd.option_context("future.distinguish_nan_and_na", True)`.
  - Removed offset aliases (now hard errors, not just deprecated): M->ME, Q->QE, Y->YE,
    BM->BME, SM->SME, BQ->BQE, BY->BYE. Worth a small mapping note.
EXTEND (present but thin):
  - Copy-on-Write: state it is now the DEFAULT and ONLY behavior in 3.0; the
    `mode.copy_on_write` option is a no-op (removed in 4.0); SettingWithCopyWarning is
    GONE; defensive .copy() no longer needed. (Sheet mentions CoW but verify it says
    "default/only in 3.0", not "opt-in".)
  - groupby idxmin()/idxmax() now raise ValueError on all-NA groups / skipna=False+NA.
UPDATE / FIX:
  - DataFrame.applymap was REMOVED in 3.0 -> use DataFrame.map (Series.map unchanged).
    Sheet still contains `applymap` (1x) AND `df.map` (1x) — verify applymap is shown
    as REMOVED/renamed, not as current API.
  - Audit for any lingering single-letter time offsets ('M','Q','Y','H','T','S') in
    date_range/resample/asfreq examples and convert to 'ME','QE','YE','h','min','s'.
Notes for HTML edit phase: additive + a few corrections; no restyle. The str-dtype
  default and applymap removal are the two must-fix items.
