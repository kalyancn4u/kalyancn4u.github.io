Ruff cheat sheet

Ruff (Rust, by Astral) is a Python linter and formatter that runs 10–100× faster than the tools it replaces — Flake8 (+dozens of plugins), Black, isort, pyupgrade, pydocstyle, bandit and more — behind two commands: ruff check (lint) and ruff format (format). Config lives in pyproject.toml. This sheet targets Ruff 0.16, which enables far more rules by default and adds # ruff: ignore line suppressions.

Run It

Two subcommands: lint and format.

1Install & the two commands0.16
  • pip install ruff # or: uv tool install ruff★
    A single prebuilt binary, no Python deps. uvx ruff ... to run without installing.
  • ruff check .★
    Lint the whole project — reports style, bugs, imports, upgrades. Exit code non-zero on findings (CI-ready).
  • ruff format .★
    Format like Black (byte-for-byte for most code). ruff format --check to verify without writing (CI).
  • ruff check --diff · ruff format --diff
    Preview changes without applying them.
2Autofix & watchfix automatically
  • ruff check --fix .★
    Auto-apply the safe fixes (unused imports, sorted imports, many rewrites). The big time-saver.
  • ruff check --fix --unsafe-fixes .★
    Also apply fixes that might change behavior — review the diff. Some rules only fix in unsafe mode.
  • ruff check --watch .
    Re-lint on file changes during development.
  • ruff check --add-noqa .
    Insert noqa comments for all current findings — a pragmatic way to adopt Ruff on a legacy codebase.

Rules

Each rule has a code; codes group into categories by the tool they came from.

3Rule codes & categoriesthe prefixes
  • E / W = pycodestyle · F = Pyflakes · I = isort★
    The essentials: style (E/W), real bugs & unused names (F), import sorting (I).
  • B = bugbear · UP = pyupgrade · SIM = simplify · C4 = comprehensions★
    High-value extras: likely bugs (B), modernize syntax (UP), simplifications (SIM/C4).
  • N = pep8-naming · S = bandit (security) · PT = pytest · D = pydocstyle
    Naming, security, test style, docstrings — each a Flake8 plugin, now built in.
  • RUF = Ruff-native · ANN = annotations · PL = pylint
    Hundreds of rules total; a code like E501 = line too long, F401 = unused import.
4Discover rulesexplore
  • ruff linter # list all rule categories★
    See every prefix and what it maps to.
  • ruff rule F401 · ruff rule --all★
    Explain a specific rule (what it flags, examples, whether it's fixable) — or dump them all.
  • ruff check --statistics .
    Count findings per rule — see what dominates before choosing what to enable/ignore.

Configure

One [tool.ruff] block controls both linter and formatter.

5pyproject.toml basicsproject config
  • [tool.ruff] line-length = 88 target-version = "py312"★
    Top-level options shared by lint & format. target-version drives which upgrades (UP) apply. Also ruff.toml standalone.
  • [tool.ruff] extend-exclude = ["migrations", "build"]
    Ruff respects .gitignore by default; add extra excludes here.
  • ruff check --config "line-length=100" .
    Override any setting inline for a one-off run.
6select / ignore / per-filechoose rules
  • [tool.ruff.lint] select = ["E", "F", "I", "B", "UP", "SIM", "C4", "N"]★
    Lint rules live under [tool.ruff.lint]. A solid, opinionated starter set. Use extend-select to add to the defaults instead of replacing.
  • ignore = ["E501"]★
    Turn rules off. Ignoring E501 (line length) is common when you let the formatter handle wrapping.
  • [tool.ruff.lint.per-file-ignores] "__init__.py" = ["F401"] "tests/*" = ["S101"]★
    Relax rules for specific paths — allow re-export unused imports in __init__, assert in tests.
  • [tool.ruff.lint.isort] known-first-party = ["myapp"]
    Sub-tables configure individual plugins (isort, pydocstyle, flake8-*).

Formatter

The Black-compatible half.

7The formatterruff format
  • ruff format .★
    Deterministic, Black-compatible formatting — a near-drop-in Black replacement, much faster.
  • [tool.ruff.format] quote-style = "double" indent-style = "space"★
    Formatter options are separate from lint. docstring-code-format = true formats code blocks in docstrings; 0.16 also formats code in Markdown.
  • select = ["I"] # let the LINTER sort imports; formatter won't★
    Import sorting is a lint rule (I), not part of format. Enable I and run check --fix to sort.
  • enable I, ignore E501 to avoid fightingtip
    When using formatter + linter together, ignore line-length (E501) in lint so the two don't disagree about wrapping.

Everyday

Silence false positives and wire into your workflow.

8Suppressing warningsnoqa
  • x = bad() # noqa: E501★
    Suppress specific rules on a line. A bare # noqa silences all — prefer naming the codes.
  • # ruff: ignore[E501] # 0.16: like noqa, incl. on the preceding line
    Newer suppression syntax; can sit on the line before the diagnostic.
  • # ruff: noqa # at top of file = ignore this file entirely # ruff: noqa: F401 # file-level, specific rule★
    File-level suppression via a comment near the top.
  • ruff check --fix --exit-zero · --output-format=github
    CI helpers: don't fail the build while adopting; emit GitHub-annotation format.
9pre-commit & editorsautomate
  • # .pre-commit-config.yaml - repo: https://github.com/astral-sh/ruff-pre-commit hooks: [{id: ruff-check, args: [--fix]}, {id: ruff-format}]★
    The standard pre-commit setup — lint (with fixes) then format on every commit.
  • ruff server # built-in language server (LSP)
    Powers the official Ruff VS Code extension and other editors — lint + format + fixes as you type.
  • ruff check --output-format=json | ...
    Machine-readable output for custom tooling/dashboards.
!Common gotchasread before shipping
  • select replaces, extend-select adds
    Setting select defines the entire active set. To keep defaults and add more, use extend-select.
  • lint config under [tool.ruff.lint]
    Since Ruff 0.2, select/ignore live under [tool.ruff.lint], not [tool.ruff]. Old top-level keys are deprecated.
  • import sorting is a lint rule, not format
    ruff format won't sort imports — enable I and run check --fix (or the pre-commit lint hook).
  • Ruff is not a type checker
    It lints & formats; it doesn't do type inference. Pair with mypy (or Astral's ty) for type checking.
  • unsafe fixes can change behavior
    --unsafe-fixes may alter semantics — review the diff and rely on tests.
